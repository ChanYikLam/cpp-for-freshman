LR-0002 · 大纲定稿：18 章，按依赖链串，终点在指针

日期：2026-10-04
来源：课设交付的「课程大纲」（curriculum.yaml）通过 check_curriculum.py 与 schema 校验

决定

课程主干定为 18 章（概念 11、实操 4、实验 3），按知识依赖排序，不跟任何教材的目录走：

  • 第 1–4 章 · 立起编译运行循环：第一个程序（写源文件 → g++ 编译 → 运行 → 看懂报错 → 改对）→ 变量、类型与内存 → 算术运算与整数除法陷阱 → 输入输出。
  • 第 5–9 章 · 让程序会思考与分工（实验一在 5）：分支 → 循环 → 函数 → 作用域与值传递。值传递留下的「函数里改了外面没变」被刻意当成悬念，它是指针的引入动机。
  • 第 10–13 章 · 一批数据放哪（实验二在 12）：数组 → 遍历统计 → 字符数组与字符串函数。
  • 第 14–18 章 · 指针（实验三在 18）：内存地址与 & → 指针与数组 → 指针作函数参数 → 空指针与陷阱 → 用指针改写系统的核心操作。

三个实验节点按项目真实路标插在中途与终点，不是堆在末尾：会编译运行 → 会存一批并统计 → 会用指针直接操作数据。

为什么这么定

  • 每个节点的开场都是真实场景问题，不是定义。第 3 章从「267 除以 3 为什么算出 89 而不是 89.0」切入整数除法，第 9 章从「函数里把成绩改成满分、回到 main 一打印还是原值」切入值传递——这两个正是零基础学生最早的「玄学 bug」，先撞上再解释，比先讲概念有效。
  • 实验课恰好 3 个、实操 4 个：每个实操/实验节点都要配一份真实可跑的 lab/ 任务树（留白任务 + solutions/ 参考解），数量必须受控，否则课件与练习会失衡。其余 11 个概念节点的动手练习写在课件正文的 ::: practice 块里（完整可编译代码 + 编译命令 + 预期输出）。
  • 大纲最初的草稿在 resources 里写了 schema 不允许的 reference 字段，且本机 python 缺 jsonschema 导致这一层校验一直被跳过——这是本轮修掉的一个真问题（见下）。

本轮暴露并修掉的工程缺口

  • schema 校验盲区：引擎的 check_curriculum.py 依赖 jsonschema，本机三个 python 都没装，它只报 [WARN] 跳过 schema 校验 就放行。也就是说「大纲 PASS」当时只等于「结构与引用完整」，字段白名单、枚举、id 正则都是没人看的。已补一个不做任何环境改动的极小 draft-07 校验器（tools/validate_schema.py，报错带 JSON 路径），并做了负例自检（故意造的坏数据能抓出「多出未定义字段」与「id 不匹配正则」两处）。以后每轮大纲、科目档案、学习进度都过它一道。

待续（下次接着做时看这里）

  • 资料收集仍在跑：本机《C++ Primer Plus 第六版》是扫描 OCR 版（文字层错字多，如 变量→变盏），定位是取章节结构与知识点顺序，正文讲法与术语以网络权威源为准。它落盘后要对齐 reference/cpp-primer-plus-6th.md 的文件名，并补上编译器环境类官方来源（g++ 用法、macOS 装 Xcode CLT、Windows 的 MinGW-w64 / Dev-C++）。
  • 课件正文与题目尚未开始：正文归讲解（每批 6 章并发，写 ::: quiz 锚点位置），题面／lab／实验说明页归出题评估。
