LR-0001 · 定下课程的交付形态与工程约束

日期：2026-10-04
来源：编写者（学习者本人）在开课盘问中的明确选择

决定

本套 C++ 课程的定位是给同专业大一新生自学的教材，不是编写者个人跟课学习。据此定下四条硬约束：

  1. 形态：产出为静态 HTML 文件夹 + 随包发布的 lab/ 代码练习目录，离线可打开（不联网、无 CDN，KaTeX 已随包带上），可整体压缩后通过微信转发，手机浏览器可读。
  2. 范围：到指针为止。不含结构体、动态内存 new/delete、类与面向对象、模板、std::vector/std::string、STL、文件读写、多文件工程。引用只在讲完取地址后作一句预告。
  3. 工程边界：kind: 实操 与 kind: 实验 的节点会各产出一个真实 lab/ 任务树（留白任务 + solutions/ 参考解），因此课型数量受控——实验课恰好 3 个、实操节点不超过 7 个，其余为概念课。概念课的动手练习写在课件正文的 ::: practice 块里（给完整可编译代码 + 编译命令 + 预期输出），不触发 lab 要求。
  4. 依据来源：首选编写者本机的《C++ Primer Plus：中文版（第六版）》，其余全网补齐；编写者明确「不用一味追求权威」，以技术结论准确、代码可编译为准。

为什么这么定

  • 交付对象是一群没有任何编程基础的新生，微信是他们的实际分发渠道。任何「需要装环境才能看」或「需要联网加载样式」的形式都会在第一屏就劝退人，所以离线自包含是硬要求，不是优化项。
  • 学习系统默认的页面引用路径是按「学习工作区」的目录形状写死的（根主页 .learning/../../assets/…、课件 ../../assets/…）。直接把渲染产物发出去会变成没有样式的裸 HTML，因此必须有一步「重排目录 + 改写相对引用」的打包流程，并用断链自检把结果看住。

由此产生的工作方式（下次续做时照这个走）

  • 课件不是手写 HTML，而是「内容文件 .md + 题库 .quiz.json → render_lesson.py → gen_home.py → build_site.py」这条链产出。
  • 改课内容改源文件，绝不手改 docs/ 里的产物（下次构建会覆盖）。
  • 发出去之前必须看到 build_site.py 打印「本地引用自检：全部可达」。
  • 仓库提交一律 GPG 签名（全局 commit.gpgsign=true，签名密钥 DA2F4CD368DE5C4F）。
