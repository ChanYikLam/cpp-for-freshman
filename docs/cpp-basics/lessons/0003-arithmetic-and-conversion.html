0003 · 算术运算与类型转换

算术运算与类型转换

本节目标：讲清整数除法为什么算出 89，并把平均分算对、让它显示成 89.0。

这一课从一个算错的平均分开始

总分 267，三个人，平均分写成 267 / 3，屏幕上却是 89，心里想的是 89.0。程序没坏，是「除法」这个词在 C++ 里有两个意思。这一课把运算符、优先级与类型转换讲清楚，让算出来的数和心里的数对上。

五个运算符与优先级

计算机上的算术靠运算符（operator）完成。运算符是告诉计算机「对这些值做一个动作」的符号。一个运算符加上它的操作数构成一个表达式（expression）——一段能算出一个值的代码。

C++ 有五个基本算术运算符：

运算符动作例子结果
+加法4 + 2024
-减法12 - 39
*乘法28 * 4112
/除法1000 / 5200
%求模（除法的余数）19 % 61

% 是 remainder（余数）的意思，读作「19 模 6」，算的是 19 除以 6 剩下的那部分：19 是 6 的 3 倍余 1。19 除以 6 的商存在，余数也存在，加法减法只给一个结果，所以除法要拆成两个运算符来问。

表达式里出现多个运算符时，先算哪个由优先级决定，这套规则和数学课上一致：先乘除、后加减。存成 arith-03.cpp，跑一遍看每个表达式算出什么。

#include <iostream>

int main()
{
    int a = 7;
    int b = 3;

    std::cout << "7 / 3 = " << a / b << std::endl;
    std::cout << "7 % 3 = " << a % b << std::endl;
    std::cout << "1 + 2 * 3 = " << 1 + 2 * 3 << std::endl;
    std::cout << "(1 + 2) * 3 = " << (1 + 2) * 3 << std::endl;
    std::cout << "1 + 2.0 = " << 1 + 2.0 << std::endl;

    return 0;
}
$ ./arith-03
7 / 3 = 2
7 % 3 = 1
1 + 2 * 3 = 7
(1 + 2) * 3 = 9
1 + 2.0 = 3

第 3 行是 1 + 2 * 3 = 7，因为 * 比 + 先算。第 4 行加了括号，括号的优先级高于所有算术运算符，所以先算加法再乘。优先级（precedence）解决的是「谁先算」，括号是你推翻默认顺序的手段，看不懂的表达式加个括号比记规则划算。

优先级相同的运算符还有一个「往哪边结合」的规则：算术运算符从左往右算，赋值运算符 = 从右往左算。average = total / kSubjectCount 里，= 右边整块先算完，结果再交给 average，这是结合性在起作用。

整数除法：89 是怎么来的

看 arith-03.cpp 的第 1 行：7 / 3 得到的是 2。

数学上 7 除以 3 是 2\frac{1}{3}。程序给出 2，说明它把小数部分丢掉了。这个规则是类型决定的：两个操作数都是整数类型时，/ 执行整数除法，结果只保留商的整数部分。小数部分被直接扔掉，这个动作叫截断（truncation）——不是四舍五入，8 / 3 得到的也是 2。

为什么会有这么个规则？因为 int 这个格子的存储规则只放得下整数，放不进 2\frac{1}{3}。要给出一个小数结果，编译器就得换一种存储规则，而它不能悄悄替你换——换了以后这个格子的类型就不是你写的那个了。所以 C++ 的选择是：运算结果按参与运算的类型来定，两个整数进去，整数出来。

把平均分算对

想让平均分带上小数，就得让这个除法至少有一个操作数是小数。三条路都能走通，存成 arith-01.cpp 编译运行：

#include <iostream>

int main()
{
    int chineseScore = 92;
    int mathScore = 88;
    int englishScore = 87;
    int total = chineseScore + mathScore + englishScore;

    int average = total / 3;
    std::cout << "整数写法：" << total << " / 3 = " << average << std::endl;

    double decimalAverage = total / 3.0;
    std::cout << "小数写法：" << total << " / 3.0 = " << decimalAverage << std::endl;

    double castAverage = static_cast<double>(total) / 3;
    std::cout << "强制转换：" << total << " 转成 double 再 / 3 = " << castAverage << std::endl;

    return 0;
}
$ ./arith-01
整数写法：267 / 3 = 89
小数写法：267 / 3.0 = 89
强制转换：267 转成 double 再 / 3 = 89

三行输出看起来一样，都是 89。这里要停一下：后两行算出来的值确实是 89.0，只是 cout 默认不显示小数点，整数级别的小数值它就印成整数样子。值和显示是两件事——第 4 课讲输出格式控制时，会把它印成 89.0。

三处改动的区别在于在哪一步换的类型：

  • int average = total / 3;：先按整数除法算出 89，再把 89 存进 int 格子。小数在第一步就没了，格子类型写 double 也救不回来。
  • double decimalAverage = total / 3.0;：3.0 是小数常量，除法按小数规则算，得到 89.0，再存进 double 格子。
  • double castAverage = static_cast<double>(total) / 3;：先把 total 从 int 换成 double，再除。

第 2 条和第 3 条为什么都能成？因为「有一个操作数已经是小数」这个条件满足了，编译器就会把它按小数规则算。

最常见的错法：换格子类型，不换运算类型 
double average = total / 3;   // 还是 89

这一行看着像「我把结果存进 double 了，应该有小数了吧」。表达式 total / 3 先算完，那时两个操作数还是 int，整数除法的规则已经生效，89 是算完的结果。后面的 double 只负责存，管不了算。要改的是运算本身，不是接收结果的格子。

练习 动手改一处 · 先把结果猜出来

把 arith-01.cpp 里的三处除法各改一次，改之前先在纸上写出你猜的结果，再编译运行对答案。猜错了就回到前面找原因：

  1. int average = total / 3; 改成分母写 3.0，接收的格子还是 int；
  2. double decimalAverage = total / 3.0; 改成 double decimalAverage = total / 3;；
  3. static_cast<double>(total) / 3 改成 static_cast<int>(decimalAverage) / 3。

第 1 处能算出小数，但存进 int 格子之后又没了；第 2 处得到 89 而不是 89.0。改对了运算、改错了格子，和改对了格子、改错了运算，是两种不同的错法——这一课的其余部分都在讲这件事。

类型转换：谁变成了谁

total / 3.0 能算出小数，是因为编译器在背后做了一件事：把 total 从 int 换成了 double。这种由编译器自动完成的转换叫隐式类型转换，规则里有几条对你有用：

  • 小的往大的转，安全。short 的值放进 long 格子、int 的值放进 double 格子，值的范围装得下，结果不变。上面这个除法用的就是这条。
  • 大的往小的转，有风险。把一个 32 亿的 long 值放进 float 格子（float 只有 6 位有效数字），这个值会被四舍五入，精度就掉了。
  • 小数转整数，小数部分直接截断。int n = 2.9; 得到的 n 是 2，不是 3。这就是整数除法丢小数的同一条规则在赋值上的样子。

自动转换很方便，但它有一个让人不放心的性质：它不会出声。你写 int average = total / 3; 而心里想的是小数，编译器一句提醒都不会给。所以 C++ 还提供一种「我要你在这里换」的写法。

比大小这一类表达式算出来的也是值。存成 arith-02.cpp 跑一下：

#include <iostream>

int main()
{
    int score = 89;

    std::cout << std::boolalpha;
    std::cout << "score < 60 -> " << (score < 60) << std::endl;
    std::cout << "score >= 60 -> " << (score >= 60) << std::endl;
    std::cout << "score >= 60 && score < 90 -> " << (score >= 60 && score < 90) << std::endl;

    return 0;
}
$ ./arith-02
score < 60 -> false
score >= 60 -> true
score >= 60 && score < 90 -> true

score < 60 这种写法叫关系表达式，它的值是 true 或 false，也就是布尔值——布尔这个词来自 19 世纪的数学家 George Boole，他建立了用代数表示逻辑推理的方法。std::boolalpha 是让 cout 把布尔值印成 true/false 而不是 1/0 的开关；&& 是「并且」，两个条件都成立才为真。这一行先当作「比大小能算出一个值」来认识，怎么用它让程序分岔，是第 6 课的事。

强制转换：把意图写出来

叫强制类型转换（type cast）的写法有两种，本课程统一用一种：

static_cast<double>(total)

static_cast 读作「静态转换」，尖括号里写你要换成的类型，圆括号里写被换的东西。它的意思是「我知道这里类型不一致，我是故意的，照我说的换」。C++ 的创造者 Bjarne Stroustrup 认为 C 语言式的强制转换写法 (double)total 太宽松、容易误用，static_cast 把「这是一次类型转换」这件事写得更显眼、检查也更严格，所以本课程用它。

上一课的 types-03.cpp 里其实已经用过它的一次隐含形态：把 char 赋给 int 格子时，编译器自动把字符编号转成了整数。同一件事写成强制转换就是 static_cast<int>(firstLetter)，把「我要它的编号」这个意图讲明白，读代码的人不用再猜。

两个必须知道的反例

反例一：对小数用 %。存成 broken-arith-01.cpp 试试：

#include <iostream>

int main()
{
    double score = 4.5;
    std::cout << score % 2 << std::endl;

    return 0;
}
broken-arith-01.cpp:6:24: error: invalid operands to binary expression ('double' and 'int')
    6 |     std::cout << score % 2 << std::endl;
      |                  ~~~~~ ^ ~
1 error generated.

% 问的是「整除以后剩下多少」，前提是先有整数除法。4.5 除以 2 没有「余数」这个概念可以用整数表示——余 0.5 里那个 0.5 本来就是被整数除法丢掉的。所以 % 的两个操作数都必须是整数类型，不是整数就编译不过。

这个报错本身是好事

double 和 int 不能一起取模，编译器在你还没运行程序的时候就拦住了。读懂 invalid operands to binary expression ('double' and 'int') 这一句：invalid operands 是「操作数不合法」，后面括号里两个类型就是它拿到的那两个操作数。这一行的意思完全可以自己读出来。

反例二：用 == 比较两个小数。这个更阴——它编译通过、运行也不报错，只是给出你不想要的结果。存成 arith-05.cpp：

#include <iostream>

int main()
{
    double a = 0.1 + 0.2;

    std::cout << "a = " << a << std::endl;
    std::cout << "0.3 = " << 0.3 << std::endl;
    std::cout << "a == 0.3 的结果：" << (a == 0.3) << std::endl;

    return 0;
}
$ ./arith-05
a = 0.3
0.3 = 0.3
a == 0.3 的结果：0

打印出来两个都是 0.3，一比却说不相等。

原因在浮点数的存储方式上：double 用二进制存小数，而 0.1、0.2、0.3 这些十进制小数在二进制里都是无限循环小数。格子里放得下的位数有限，所以它们都是「最接近的近似值」。近似值相加之后，误差凑巧没有抵消，0.1 + 0.2 的结果和 0.3 那个近似值差在最后几位上。cout 默认只印 6 位有效数字，把差异盖住了，所以看起来一样。

结论：浮点数永远不要用 == 判断相等。要比的话，比较两个数之差的绝对值是否小于某个很小的数（比如 0.000001），这条路留到后面讲函数时再写。
