0002 · 变量、类型与内存

变量、类型与内存

本节目标：用 int、double、char 声明变量，用它们算出一份总分，并且看懂整数与小数在结果上的差别。

这一课从「内存格子」出发

一门课的成绩，总分要算加法，平均分要算小数，还有名字首字母只是一个字母。这三样东西为什么不能都用同一个写法存？这一课讲清「格子、名字、类型」三件事的关系，以及编译器在背后替你做了什么。

为什么需要「变量」

先说一个前提：程序里的数字不能凭空存在。它必须落在内存的某个位置上。

内存可以想成一排编了号的房间，每个房间能放一点点数据。要往里面放一个成绩，程序必须交代三件事：

  • 数据放在哪个房间；
  • 这个房间放什么值；
  • 这个房间里的二进制位，按哪种规则来解释。

第三件事最容易被忽略。同一个房间里的同一串二进制位，按整数解释是 65，按字符解释就是字母 A——房间本身不知道自己在存什么，是解释规则决定了它的含义。

于是 C++ 要求你在往房间里放东西之前，先把房间认下来、给它起个名字、并且说明按哪种规则解释。这套做法给出的东西叫变量：内存里一块有名字的存储空间，用来存一个会变的值。

变量之所以能省事，是因为它把「哪个房间」这件事接管了。以后你在代码里写 chineseScore，编译器替你换算成那个房间的位置。否则每次想用这个成绩，你都得自己记住一串地址，程序也就没法读了。

声明：给格子起名字

让编译器划出格子并起名字，这条语句叫声明（declaration）。先看一份能跑的代码。把它存成 types-01.cpp 再编译。

#include <iostream>

int main()
{
    int chineseScore = 92;
    int mathScore = 88;
    int englishScore = 87;
    int total = chineseScore + mathScore + englishScore;

    std::cout << "三科总分：" << total << std::endl;

    return 0;
}
g++ types-01.cpp -o types-01 && ./types-01
$ ./types-01
三科总分：267

四行声明的形状是一样的：数据类型 名字 = 初始值;。int chineseScore = 92; 读作「划一块能放整数的格子，名字叫 chineseScore，一开始放 92」。

int 是 数据类型（data type）：它规定了这块存储空间能存什么、占多大、怎么解释这些二进制位。C++ 把「占多大」和「怎么解释」都交给类型名来回答，所以在 C++ 里声明变量时类型不能省。

这里有个与 Python 的对照值得说一句：Python 里写 x = 1 直接用就行，类型由运行时的值决定；C++ 要在写代码的时候就说清类型。付出的代价是多敲一个 int，换来的是编译器能在编译的时候就告诉你「你把一个名字赋值给了整数格子」——这类错误在程序跑起来之前就被拦住了。

为什么不能只有一种类型

int 只放得下整数。成绩要算小数平均分，int 就装不下了。于是一个念头很自然：那所有格子都按小数规则解释不就行了？

不行，理由有两个，都跟内存的物理形态有关。

第一，小数和整数的存储规则完全不同。整数的位直接拼成数值（二进制）；小数要拆成「基准值」和「缩放因子」两部分，缩放因子负责移动小数点的位置——「浮点」这个名字就是这么来的。同一串位按两种规则解释会得到毫无关系的两个数，所以规则必须在声明时就定下来，编译器才知道该生成哪种指令。

第二，格子的大小是有限的，而不同的用途需要的范围不一样。int 通常占 4 个字节（32 位），能表示的整数上限是 2147483647；再大就需要 long long，占 8 个字节。如果只有一个「万能类型」，要么不够用，要么平白浪费内存。

C++ 的做法是给出一组基本类型，各管一段范围。本课程要用的三个：

类型用来存什么常见大小写法
int整数，比如成绩、人数4 字节int score = 92;
double带小数的数，比如平均分8 字节double average = 89.0;
char单个字符，比如等级 A1 字节char grade = 'A';

int 是 integer（整数）的缩写，double 的名字来自「双精度」——它的有效位数是 float 的两倍，能多存 7 位左右的有效数字。要算的数是成绩平均分这种量级时，用 double 就够，float 反而会在乘除之后一点点累积误差：经典教材里同一个 10.0 / 3.0，float 放大一百万倍后开始对不上，double 还能对上十几位。

char 为什么要单独一个类型：字符和整数在内存里其实是同一类东西。字符 A 存进去的是它对应的编号 65，B 是 66。既然都占一个字节，用 int 存字符也能存得下。声明成 char 的意义在于解释方式：编译器看到 char，就知道你要它按字符的样子显示；看到 int，就按编号的数字显示。这个编号体系叫 ASCII。

char 的值可以用编号展示出来。存成 types-03.cpp，编译运行：

#include <iostream>

int main()
{
    char firstLetter = 'L';
    int letterCode = firstLetter;

    std::cout << "首字母是 " << firstLetter << std::endl;
    std::cout << "它的编码是 " << letterCode << std::endl;

    firstLetter = firstLetter + 1;
    letterCode = firstLetter;
    std::cout << "再加 1，字符变成 " << firstLetter
              << "，编码变成 " << letterCode << std::endl;

    return 0;
}
$ ./types-03
首字母是 L
它的编码是 76
再加 1，字符变成 M，编码变成 77

L 的编号是 76，M 是 77。字母在 ASCII 表里是挨着排的，所以给字符加 1 就等于顺着往下挪一个字母。assert 一下这个观察很重要：字符在内存里就是编号，char 只是让编译器按字母的样子给你看。

初始化：读不到值的那种错

int total; 这样只声明、不给初始值，也是合法的。但接下来如果直接拿它做加法，读到的是一串来路不明的值。

原因是内存不擦。上一段程序用过的格子，操作系统直接交给下一段程序接着用，里面留着什么就是什么。C++ 为了性能，声明时不会替你把格子清成 0，所以那个值可能是 0、可能是 1610612736，每次跑还可能不一样。这类现象在 C++ 里叫未定义行为：标准没有规定结果是什么，编译器也没有义务帮你兜底。

规矩：声明变量时顺手给它一个初始值。想不出合理的初值，就给 0。这一条能省掉一大类「跑一次对、跑一次错」的怪事。

常量与 const

有一类数字不该变：一门课固定三门，一石等于 14 磅，一个月 12 个月。这种数字写进代码叫字面值，但直接写数字有个麻烦：

double average = total / 3;

三周后回来看，3 是什么？是科目数，还是别的什么？而且以后科目从三门改成五门，你得在程序里把每个 3 都找出来——漏掉一个就出错。

办法是给这个数字起个名字，并且声明它不许被改。做法是在类型前面加关键字 const：

const int kSubjectCount = 3;

const 是 constant（常量）的缩写，它叫限定符：它限定了这条声明里变量的值固定下来，之后任何想给它赋值的代码都会被编译器直接拦下。这样「科目数」这个名字只有一个定义处，改一处就全改了。

const int kSubjectCount;

这一行是错的。存成 broken-types-01.cpp 编译一下，报错是这样的：

broken-types-01.cpp:5:15: error: default initialization of an object of const type 'const int'
    5 |     const int kSubjectCount;
      |               ^            
      |                             = 0

default initialization of an object of const type 的意思是「一个 const 类型的对象被默认初始化了」——也就是没给值就放着了。原因是常量必须在声明的时候就给出值：值一旦固定就不允许再改，那么声明时不给值，这个名字就永远拿不到值了。注意编译器最后那行给的建议 = 0：它甚至替你想好了改法。

这一条和上面「顺手给初值」是同一个毛病的两种表现，但 const 这种更严重——编译器会直接拦住你，这是好事，比跑到一半读出乱值好得多。

命名上，常量用小写字母 k 打头（kSubjectCount）是一种常见约定，一看就知道它不是普通变量。

亲手试一遍

练习 第 1 步 · 声明几个变量，看总分

把下面的程序存成 types-02.cpp 编译运行。它和 types-01.cpp 只差一行：把总分除以 3 得到平均分。

#include <iostream>

int main()
{
    int chineseScore = 92;
    int mathScore = 88;
    int englishScore = 87;
    int total = chineseScore + mathScore + englishScore;
    double average = total / 3;

    std::cout << "总分：" << total << "，平均分：" << average << std::endl;

    return 0;
}
$ ./types-02
总分：267，平均分：89

平均分是 89，不是 89.0，也不是 89.666…。这不是打印格式的毛病，average 这个格子里真的就是 89——下一课专门拆这一处。

练习 第 2 步 · 改一处，看类型怎么影响结果

把 double average = total / 3; 的三处改动分别试一次，每次改完重新编译运行，记下输出：

  1. 把 average 的声明改成 int average = total / 3;；
  2. 把 3 改成 3.0；
  3. 把 total 的声明改成 double total = chineseScore + mathScore + englishScore;。

编译运行还是那条命令：

g++ types-02.cpp -o types-02 && ./types-02

第 1 处改完，输出里连小数位都没了：

$ ./types-02
总分：267，平均分：89

第 2 处开始能算出小数。哪一处改动能改变结果、为什么能，就是下一课的全部内容。

练习 第 3 步 · 造一个未定义行为，再治好它

新写一份文件：声明 int total; 之后不给值，直接打印它，编译运行两三次，看每次打印的是不是同一个数。照着上面那条命令编译（把文件名换成你自己的）。

g++ uninit.cpp -o uninit && ./uninit

三次运行的输出长这样——每次都可能不一样：

$ ./uninit
1610612736
$ ./uninit
32767
$ ./uninit
-1073743896

然后把这一行补成 int total = 0; 再跑三次，输出就每次都一样了：

$ ./uninit
0

编译通过、运行也没有报错，可那个数在两次运行之间会变。这就是「顺手给初值」这条规矩的由来：你没法预测那个格子原来装着谁的什么数据。
