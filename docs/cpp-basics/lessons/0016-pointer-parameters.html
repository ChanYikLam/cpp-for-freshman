指针作函数参数

本节目标：把统计函数改成接收指针参数的版本，函数里改的数据调用方也能看到

第 14 章用指针改动了同一个 main 里的变量。这一课把这件事搬到函数之间：把整张成绩表交给函数，函数在里面改，main 里那张表跟着变。这是本项目所有统计函数的前提。

数组传参传的是什么

先看一个具体的问题。上一课的 parr-03.cpp 把统计写在 main 里，代码一多就乱。想把它拆成函数，第一个念头大概是这样：函数接收一个数组，返回总分。

存成 pparam-00.cpp 再编译：

// pparam-00.cpp -- 先试试"函数接收一个数组"最想写的样子
#include <iostream>
using namespace std;

int total(int table[5])         // 形参写成数组的样子
{
    int sum = 0;
    for (int i = 0; i < 5; i++)
        sum = sum + table[i];
    return sum;
}

int main()
{
    int scores[5] = {88, 76, 95, 60, 82};
    cout << "总分：" << total(scores) << endl;
    return 0;
}
$ g++ pparam-00.cpp -o pparam-00
$ ./pparam-00
总分：401

能跑，但这段代码里藏着一层容易被忽略的事实：形参 table 并不是一个数组。数组没法整个儿搬进函数——scores 里装着 5 个 int，函数调用时不会把这 5 个格子复制一份。

真正传过去的是 scores 这个地址，也就是第一个元素的地址。形参 table 收到这个地址，它是一个指针。table[5] 里那个 5 编译器根本不看，写成 int table[100] 或者 int *table 效果一样。

传参的副本恰好还指着同一片内存

第 9 章说「函数拿到的是实参的副本」，现在这条规则和数组接上了。把这两件事连起来推一遍：

  1. total(scores) 调用时，实参是 scores 这个地址；
  2. 值传递的规则是复制一份，所以形参 table 拿到的是这个地址的副本；
  3. 副本和原件是同一个数字，指向同一片内存；
  4. 函数里通过 table 访问到的元素，就是 main 里 scores 的那些元素。

结论：数组传给函数时，改动会在调用方看到。这一条可以从「副本里装的是地址」直接推出来，不需要另外记一条规则。

存成 pparam-01.cpp 再编译：

// pparam-01.cpp -- 同一个变量，函数里看到的和外面看到的是不是同一个
#include <iostream>
using namespace std;

void tryByValue(int x)          // 形参不是指针：拿到的是副本
{
    x = 100;
    cout << "  函数里（值传递）x 现在是 " << x << endl;
}

void tryByPointer(int *p)       // 形参是指针：拿到的是地址
{
    *p = 100;
    cout << "  函数里（指针）*p 现在是 " << *p << endl;
}

int main()
{
    int score = 60;

    cout << "调用前 score 是 " << score << endl;
    tryByValue(score);
    cout << "值传递之后 score 是 " << score << endl;

    tryByPointer(&score);
    cout << "指针传参之后 score 是 " << score << endl;

    return 0;
}
$ g++ pparam-01.cpp -o pparam-01
$ ./pparam-01
调用前 score 是 60
  函数里（值传递）x 现在是 100
值传递之后 score 是 60
  函数里（指针）*p 现在是 100
指针传参之后 score 是 100

对照着看：tryByValue 改的是副本，score 没变；tryByPointer 收到地址，走进去改的是 score 本人。区别只在形参写的是 int 还是 int *。

指针形参怎么用：统计函数

把上一课写在 main 里的统计拆成三个函数：两个只看不改，一个要改。

存成 pparam-02.cpp 再编译：

// pparam-02.cpp -- 把统计写成接收指针的函数
#include <iostream>
using namespace std;

int total(const int *p, int n)      // 只看不改，加 const 让编译器帮忙看着
{
    int sum = 0;
    for (int i = 0; i < n; i++)
        sum = sum + p[i];
    return sum;
}

int highest(const int *p, int n)
{
    int top = p[0];
    for (int i = 1; i < n; i++)
        if (p[i] > top)
            top = p[i];
    return top;
}

void addBonus(int *p, int n, int bonus)   // 要通过指针改调用方的数据
{
    for (int i = 0; i < n; i++)
        p[i] = p[i] + bonus;
}

int main()
{
    int scores[5] = {88, 76, 95, 60, 82};

    cout << "总分：" << total(scores, 5) << endl;
    cout << "最高分：" << highest(scores, 5) << endl;

    addBonus(scores, 5, 2);         // 全班各加 2 分

    cout << "加分后：";
    for (int i = 0; i < 5; i++)
        cout << scores[i] << " ";
    cout << endl;

    return 0;
}
$ g++ pparam-02.cpp -o pparam-02
$ ./pparam-02
总分：401
最高分：95
加分后：90 78 97 62 84

三个函数都用指针形参，但传进去的都是 scores，没有一处写 &。原因在上一节：数组名本身就是地址。

addBonus 调用后，main 里的 scores 每一项都加了 2，打印出来是 90 78 97 62 84。这就是「函数真的改到了调用方的数据」。

请注意每个函数都多带了一个 n。数组交给函数的时候，长度不会跟着过去——函数只知道起点在哪，不知道有几格。

只读参数与 const

total 和 highest 只是读表，不会改任何元素。调用方看到 const int *p 就明白这一点：这个函数不会动我的数据。

const 写在 * 左边，意思是「顺着 p 读可以，通过 p 写不行」。

存成 pparam-04.cpp 再编译：

// pparam-04.cpp -- 反例：标了 const 却还想改
#include <iostream>
using namespace std;

int total(const int *p, int n)
{
    int sum = 0;
    for (int i = 0; i < n; i++)
    {
        sum = sum + p[i];
        p[i] = 0;           // 想把读过的格子清零，编译器不允许
    }
    return sum;
}

int main()
{
    int scores[5] = {88, 76, 95, 60, 82};
    cout << total(scores, 5) << endl;
    return 0;
}

这个程序编译不过，报错大意是：

error: read-only variable is not assignable

编译器在这一行拦住了对只读数据的写入。把 const 去掉就能编译通过——但那时调用方就看不出这个函数会不会改自己的数据了。

什么时候加 const

只读的函数加 const：一是把「我不改你的数据」写成代码，看函数声明就知道；二是自己写错时编译器会拦下来；三是调用方传常量进来时不会报错。要改数据的函数（addBonus 这类）就不加。

存成 pparam-05.cpp 再编译。这张表上，total 只读、everyonePass 要改，两个形参写法不同，一眼看得出来谁动数据：

// pparam-05.cpp -- const 与不带 const 的形参，用一张成绩表看清楚
#include <iostream>
using namespace std;

int total(const int *p, int n)      // 只读：加 const
{
    int sum = 0;
    for (int i = 0; i < n; i++)
        sum = sum + p[i];
    return sum;
}

void everyonePass(int *p, int n)    // 要改：不加 const
{
    for (int i = 0; i < n; i++)
        if (p[i] < 60)
            p[i] = 60;
}

int main()
{
    int scores[3] = {88, 45, 30};

    cout << "改之前总分：" << total(scores, 3) << endl;

    everyonePass(scores, 3);

    cout << "改之后总分：" << total(scores, 3) << endl;
    cout << "改之后成绩表：" << scores[0] << " " << scores[1] << " " << scores[2] << endl;

    return 0;
}
$ g++ pparam-05.cpp -o pparam-05
$ ./pparam-05
改之前总分：163
改之后总分：208
改之后成绩表：88 60 60

45 和 30 都被提到了 60，总分从 163 变成 208。这一处改动发生在函数里，看到变化的是 main。

形参里的 sizeof 量不到数组长度

长度必须自己传进去，还有一个原因是函数里根本量不出来。

存成 pparam-03.cpp 再编译：

// pparam-03.cpp -- 形参里的 sizeof 量不到数组的长度
#include <iostream>
using namespace std;

int total(const int *p, int n)      // 形参 p 是一个指针
{
    cout << "函数里 sizeof(p) = " << sizeof(p) << " 字节" << endl;
    int sum = 0;
    for (int i = 0; i < n; i++)
        sum = sum + p[i];
    return sum;
}

int main()
{
    int scores[5] = {88, 76, 95, 60, 82};

    cout << "main 里 sizeof(scores) = " << sizeof(scores) << " 字节" << endl;
    cout << "也就是说这个数组有 " << sizeof(scores) / sizeof(scores[0]) << " 个元素" << endl;

    cout << "总分：" << total(scores, 5) << endl;

    return 0;
}
$ g++ pparam-03.cpp -o pparam-03
$ ./pparam-03
main 里 sizeof(scores) = 20 字节
也就是说这个数组有 5 个元素
总分：函数里 sizeof(p) = 8 字节
401

同样的写法，在两处得到完全不同的结果：main 里 sizeof(scores) 是 20（5 个 int），函数里 sizeof(p) 是 8（一个地址）。

原因是 main 里 scores 是一个数组，函数里 p 是一个指针。上一课留下的那条边界在这里变成了实际的 bug：函数里写 int n = sizeof(p) / sizeof(p[0]); 会算出 8 / 4 = 2，循环只走两格，统计出来的总分只有前两个成绩的和。

所以长度要当成另一个参数传进去：total(scores, 5)。这是 C 风格数组写法的固定搭配——起点加长度，两个一起给。

动手改写统计函数

前面五个程序按顺序敲一遍，重点是把 pparam-03.cpp 和 pparam-04.cpp 的报错自己看一眼。

练习 第 1 步 · 把求平均写成指针参数版

在 pparam-02.cpp 里加一个函数 double average(const int *p, int n)，返回平均分。在 main 里调用它，打印出 80.2。

练习 第 2 步 · 让函数改到调用方

再加一个函数 void curveAll(int *p, int n)，把每个成绩按「不到 60 的提到 60」处理。调用后打印 main 里的 scores，确认 60 分以下的那项真的变了。

练习 第 3 步 · 故意把长度写错

把 total(scores, 5) 改成 total(scores, 2) 编译运行，看总分变成多少。再把它改成 total(scores, sizeof(scores) / sizeof(scores[0]))，确认这一次结果是对的。

这一步要把「长度必须一起传」这句话变成自己踩过的一次。
