函数：把一段活儿打包

本节目标：把求平均的那段逻辑包成一个函数，在 main 里调用它并把结果打印出来。

同一段逻辑抄了三遍

成绩管理系统里，「求平均」这件事会在好几个地方出现：统计的时候要打一份平均分，打印成绩单的时候要写一行平均分，排名的时候还要拿平均分做比较。

上一章我们把求平均写成了这样几行：

double sum = 0.0;
for (int i = 0; i < n; i++)
    把成绩加进 sum
double average = sum / n;

这段逻辑要是抄三遍，麻烦就来了：哪天要求改成「去掉一个最高分再算平均」，三个地方都得改，漏掉一处，同一份数据算出来的平均分就不一样了。

更好的做法是给这段活儿起个名字，写一次，以后按名字用它。

函数：把一段活儿打包

函数：把一段完成特定任务的代码打包起来、起个名字，需要时按名字调用。打包的目的有两个：同一段逻辑只写一次就能用很多次；一段代码只负责一件事，出了问题也知道去哪儿找。

「函数」这个词在数学里已经有了，含义也相近：给一批输入，按固定规则算出结果。C++ 借用了它，但多了一件数学里没有的事——函数还可以只干活、不交结果，比如在屏幕上打印一行字。

C++ 里用上一个函数，要做三件事：

要做的事写在哪儿少了它会怎样
函数定义写在源文件里，交代这个函数叫什么、吃什么、干什么编译器找不到这个名字，链接时失败
函数原型写在调用它之前，交代它吃什么、交回什么编译器读到调用时信息不足，报错或悄悄按默认规则处理
函数调用想用它的地方，写名字加一对括号这个函数永远不会被执行

这三件事的写法，看一遍完整的程序就清楚了。

定义、原型、调用

存成 func-01.cpp 再编译：

// func-01.cpp -- 使用一个函数的三个步骤：定义、原型、调用
#include <iostream>
using namespace std;

void printLine();            // 函数原型
int add(int a, int b);       // 函数原型

int main()
{
    printLine();
    int total = add(90, 85);          // 函数调用
    cout << "两个成绩相加：" << total << endl;
    printLine();
    return 0;
}

void printLine()             // 函数定义
{
    cout << "--------------------" << endl;
}

int add(int a, int b)        // 函数定义
{
    return a + b;                   // 返回值
}
$ g++ func-01.cpp -o func-01
$ ./func-01
--------------------
两个成绩相加：175
--------------------

程序里三样东西各自的位置和职责：

  • 函数定义由两部分组成。第一行是函数头：最前面的 int 说明这个函数交回一个整数，add 是它的名字，括号里的 int a, int b 是它接收数据的两个位置。花括号里的那组语句是函数体，也就是这个函数真正干的活儿。
  • 函数原型只保留函数头的信息，末尾写一个分号。它告诉编译器：add 这个函数吃两个 int，交回一个 int。原型的形参名可写可不写，写成 int add(int, int); 一样管用；写上名字是为了读代码的人看得明白。
  • 函数调用就是写名字加括号，括号里给数据。add(90, 85) 这个调用本身就是一个表达式，它的值就是函数交回的结果，所以可以直接赋给 total。

程序从 main 开始执行。执行到 printLine(); 这一行时，main 先停在这里，转去执行 printLine 的函数体，函数体跑完再回到这一行的下一句继续。这也是为什么输出里那两条横线一前一后夹着中间那行字。

形参、实参与数据流向

上一步出现了两组名字很像的东西，需要分清楚。

形参 / 实参：函数定义里写的、用来接收数据的占位名字叫形参；调用时真正传进去的值叫实参。这对词的存在，是因为「参数」两个字同时指着两个不同的东西：定义处那个名字，与调用处那个具体的值。只说「参数」，就说不清「改的到底是哪一个」。

返回值：函数执行完交回给调用者的那个结果，用 return 语句交回。函数头最前面写的那个类型，就是这个返回值的类型。

规则有三条：

  • 实参的个数、类型、先后顺序，要与形参一一对上。add(90, 85) 的两个实参分别落到形参 a 和 b，第一个进 a，第二个进 b，顺序换了结果就换了。
  • return 后面可以写常量、变量，也可以写一个表达式。写表达式时，先把表达式的值算出来，再交回调用处。
  • 函数头写 void 表示这个函数不交回结果，此时函数体里可以写 return; 表示提前收工，但后面不能跟值。printLine 就是这样的函数。

把求平均包成函数

把开头那段抄了三遍的逻辑收进一个函数：交给它总分和人数，它交回平均分。测这个函数用的输入，就是上一章 loops-02.cpp 里那 5 个成绩。

存成 func-02.cpp 再编译：

// func-02.cpp -- 把求平均包成一个函数，在 main 里调用它
#include <iostream>
using namespace std;

double average(double sum, int count);      // 函数原型

int main()
{
    int n;
    cout << "请输入成绩个数：";
    cin >> n;

    double sum = 0.0;
    for (int i = 0; i < n; i++)
    {
        double score;
        cin >> score;
        sum += score;
    }

    cout << "总分：" << sum << endl;
    cout << "平均分：" << average(sum, n) << endl;      // 函数调用
    return 0;
}

double average(double sum, int count)       // 函数定义
{
    return sum / count;                     // 返回值
}
$ g++ func-02.cpp -o func-02
$ ./func-02
请输入成绩个数：5
90
85
78
92
88
总分：433
平均分：86.6

读这段代码时最该注意的，是哪些东西要传进去，哪个结果要带出来：

  • average 需要两个信息才能干活：总分与人数。它们就是两个形参。
  • 它交回的是平均分，所以函数头的类型写成 double。写成 int 的话，433 / 5 的结果 86.6 会被截成 86，函数里算得再对也没用。
  • return sum / count; 里 sum 是 double，count 是 int，两个数相除得到的是小数。小数能留下来，靠的是 sum 的 double 类型。

改用函数以后，main 里剩下的都是「读数据、调函数、打结果」这类一眼能看懂的动作，具体怎么算被挪进了 average。求平均的规则要改，只改函数体那一处。

默认值与同名函数

函数定好以后，还会遇到两种调整它的场合。

参数默认值：在函数原型里给形参写上一个默认值，调用时可以不写这个实参，编译器用默认值补上。

为什么需要它：同样是打印一份成绩，多数时候是百分制，偶尔是 150 分制。两种都写成函数也行，但名字得区分开；给末尾那个形参一个默认值，调用处就能少写一个实参。

存成 func-03.cpp 再编译：

// func-03.cpp -- 参数默认值：调用时可以不写末尾那个实参
#include <iostream>
using namespace std;

void printScore(int score, int full = 100);      // 末尾的形参有默认值

int main()
{
    printScore(86);          // 只传一个实参，full 用默认值 100
    printScore(86, 150);     // 传两个实参，full 取 150
    return 0;
}

void printScore(int score, int full)
{
    cout << score << " / " << full << endl;
}
$ g++ func-03.cpp -o func-03
$ ./func-03
86 / 100
86 / 150

默认值有两个要点：写在原型里，定义里不再重复写；默认值要从形参表的最右边开始，中间不能空。void printScore(int score = 60, int full = 100); 是允许的，而只给第一个形参默认值、第二个不给，是不允许的。

函数重载：同一个名字下可以有多个函数定义，只要它们的形参表不同，编译器会根据实参的个数和类型挑一个来用。

为什么需要它：成绩有时是整数 86，有时是小数 86.5，处理方式不同，但都是「显示一份成绩」。让它们共用一个名字，调用的时候不用记住两套名字。

存成 func-04.cpp 再编译：

// func-04.cpp -- 函数重载：同名函数，靠实参对号入座
#include <iostream>
using namespace std;

void show(int score);
void show(double score);
void show(int score, int full);

int main()
{
    show(86);            // 一个 int 实参，匹配 show(int)
    show(86.5);          // 一个 double 实参，匹配 show(double)
    show(86, 150);       // 两个 int 实参，匹配 show(int, int)
    return 0;
}

void show(int score)
{
    cout << "整数成绩：" << score << endl;
}

void show(double score)
{
    cout << "带小数的成绩：" << score << endl;
}

void show(int score, int full)
{
    cout << "成绩 " << score << "，满分 " << full << endl;
}
$ g++ func-04.cpp -o func-04
$ ./func-04
整数成绩：86
带小数的成绩：86.5
成绩 86，满分 150

重载看的是形参表。两个函数只有返回值类型不同、形参一模一样，编译器无法从调用处分辨该用哪一个，这种不算重载，会直接报错。

返回值路径要走全

有返回值的函数，每一条能走到末尾的路径都必须交回一个值。漏了一条，函数返回给调用处的东西就没有意义了。

存成 func-05.cpp。这个程序编译得过，但只用来看报错，不要去运行：

// func-05.cpp -- 反例：分支里的 return 漏了一条路径
#include <iostream>
using namespace std;

int level(int score)
{
    if (score >= 60)
    {
        return 1;
    }
    // 成绩小于 60 时没有 return，函数直接走到末尾
}

int main()
{
    cout << level(75) << endl;
    cout << level(40) << endl;      // 这里打印出来的值没有意义
    return 0;
}
加了 -Wall 才看得见的提醒

-Wall 是 g++ 的一个选项，意思是「把编译器能发现的疑点都提醒出来」（w 是 warning 的首字母）。它不改程序的行为，只是多打印一些提醒。用 g++ -Wall func-05.cpp -o func-05 编译时，编译器会明确提醒：

$ g++ -Wall func-05.cpp -o func-05
func-05.cpp:12:1: warning: non-void function does not return a value in all control paths [-Wreturn-type]

意思是「声明了交回值，但不是所有分支都会交回」。score >= 60 时函数在 if 里就返回了；score < 60 时，函数一路走到末尾的右花括号，交回的是一个没有意义的值。补一条 return 0; 或者在末尾统一返回，都能解决。

不带 -Wall 也能编译通过，这条提醒就看不见了——所以编译时把 -Wall 带上。

另一种错法编译器直接拦住。存成 func-06.cpp：

// func-06.cpp -- 反例：void 函数里 return 一个值
#include <iostream>
using namespace std;

void printScore(int score)
{
    cout << "成绩：" << score << endl;
    return score;          // 编译错误：void 函数不能交回一个值
}

int main()
{
    printScore(86);
    return 0;
}
void 函数不能交回值

编译这个文件，编译器会报错并停在 return score; 那一行：

$ g++ func-06.cpp -o func-06
func-06.cpp:8:5: error: void function 'printScore' should not return a value

函数头写着 void，等于向编译器承诺「这个函数不交回结果」，return score; 就与这个承诺冲突了。想让 printScore 交回成绩，就把函数头的 void 改成 int；想让它继续只打印，就把这一行删掉。

main 的返回类型是 int，return 0; 表示程序正常结束，这一处在第 1 课已经见过。

动手做：改一行看变化

函数的知识点不多，手感却要靠改代码来建立。下面三步都在刚才那几个文件上改，每一步都能立刻看到结果。

练习 改一行，看结果变在哪里

第 1 步 · 改返回值。把 func-02.cpp 里 average 的 return sum / count; 改成 return sum;，重新编译运行，看「平均分」那一行变成了什么；再改成 return count; 看一次。

第 2 步 · 改函数头的类型。把 double average(double sum, int count) 的 double 改成 int，重新编译运行。平均分后面小数没了，想一想这个小数是在哪一步丢掉的。

第 3 步 · 少传一个实参。把 func-03.cpp 里 printScore(86, 150); 改成 printScore(86);，运行看输出；再把原型里的 = 100 删掉，重新编译，看编译器怎么说。

三步都做完，顺手回到 func-05.cpp，把漏掉的那条 return 补上，再编译一次，看那条警告是不是消失了。
