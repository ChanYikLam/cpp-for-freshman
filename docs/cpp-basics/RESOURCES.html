C++ 零基础入门（计算机专业大一） Resources

定位：延伸阅读 + 易变内容的核对来源，不是"知识来源清单"（模型已掌握稳定基础知识）。
稳定知识节点可以不在这里留条目；易变/版本相关内容必须在这里有核对过的官方来源。

范围锚点：到指针为止（基础语法、变量与类型、运算符与表达式、分支、循环、函数、数组、C 风格字符串、指针），
不含结构体、动态内存 new/delete、类与面向对象、模板、std::vector/std::string、STL、文件读写、多文件工程。
本清单里凡涉及范围外内容的条目，用途一栏都显式标了「范围外，仅防越界」。

第三项 = 实际落点路径（本轮修正）：每条资源的第三个字段写的是它现在真正躺在哪：
- 已落盘的在线来源正文 → sources/<文件名>.md（不是 fetch/，本机没有 fetch/ 这个目录）
- 只抓到 HTML、没转 md 的 → raw_html/<文件名>.html（在 stage 目录里，见文末「机器可读附录」）
- 本地教材 → reference/<文件名>.md
- 取不到正文的（纸书、403 站点）→ 只留原址 URL，并在条目里写明"只有原址"
上一轮有一批条目第三项只写了 sources/xxx.md 而没写清这是科目根下的相对路径，本轮全部补全为可定位的路径或 URL。

  • Source: github.com/Embarcadero/Dev-Cpp · 仓库元数据 / 全部发布版本 / README（GitHub 官方 API 取证） · 已落盘 sources/devcpp-status-2026.md
    Dev-C++ 现状事实单：现维护方是 Embarcadero（不是 Bloodshed）；最后一个正式版本 v6.3，发布于 2021-01-31，此后未再发版；仓库最后代码 push 是 2024-06-17；未被 GitHub 归档但版本停更；内置编译器为 TDM-GCC 9.2（对应 GCC 9.2，2019 年）。用途：课程要如实告知 Windows 读者"Dev-C++ 能装、能编，但已停更"，本文件是这件事的证据（含 Releases 直链，因为 SourceForge 已 403）。
  • Source: LearnCpp 0.6 · IDEs to avoid（权威方的反对意见，原文照录） · 已落盘 sources/lc-00-06-installing-an-ide.md
    该页「IDEs to avoid」一节的原文是："You should avoid the following IDEs altogether because they do not support at least C++11, do not support C++ at all, or are no longer actively supported or maintained: Borland Turbo C++ …; Visual Studio for Mac …; Dev C++ -- not actively supported"。用途：课程若保留 Dev-C++ 这条路，必须同时把这条反对意见如实写进课件——不是假装它没问题，而是告诉读者"它停更了，你可能只是在学校机房遇到它"。
  • Source: Apple 官方 · Installing the command-line tools（xcode-select --install 的正规出处） · 已落盘 sources/apple-installing-command-line-tools.md
    macOS 装编译环境这一节的唯一官方依据：工具链装在 /Library/Developer/CommandLineTools；xcode-select --install 的确切命令与提示语；pkgutil --pkg-info=com.apple.pkg.CLTools_Executables 查版本；sudo rm -rf 卸载。用途：macOS 读者照着敲。
  • Source: Apple 官方 · Technical Note TN2339: Building from the Command Line with Xcode FAQ · 已落盘 sources/apple-tn2339-xcodebuild.md
    用途：核对 xcode-select / xcrun / /usr/bin/clang 三者的关系；支撑"macOS 上命令行里的 clang 来自 Command Line Tools"这一说法（配合下一条的实测）。
  • 本机实测记录（不是外部来源，是环境事实，供讲解引用）：macOS 15.7.5 (24G624)、Command Line Tools 路径 /Library/Developer/CommandLineTools，
    /usr/bin/g++、/usr/bin/gcc、/usr/bin/clang++、/usr/bin/clang 四个路径指向同一个 inode（stat -f %i 全部相同，链接数 78），
    g++ --version 输出 Apple clang version 17.0.0 (clang-1700.0.13.5)。
    这就是讲解里「macOS 上 g++ 其实是 Apple clang 的别名」的依据；复现命令：stat -f '%i %N %l links' /usr/bin/g++ /usr/bin/clang++。
