术语表 · 大白话版

这份术语表是给完全没接触过计算机的同学准备的：每个词都先拿生活里的东西打比方，让你先「感觉到」它是干什么的，再给准确的说法。

这份和另一份的关系

课程还有一份规范版术语表（点这里），定义更精确、还标了「不要用哪个说法代替它」。

两份讲的是同一批词，不冲突。建议：看不懂某个词时先翻这份；等你学过几章、想确认准确说法时，再去看规范版。

按主题找词

  • 程序是怎么跑起来的：源文件 · 编译 · 链接 · 可执行文件 · 标准库
  • 存数据：变量 · 数据类型
  • 写指令：运算符 · 表达式 · 语句
  • 把活儿打包：函数 · 形参 / 实参 · 返回值 · 值传递 · 作用域 · 变量生命周期
  • 存一批数据：数组 · 下标 · C 风格字符串
  • 地址与指针：内存地址 · 指针 · 取地址运算符 & · 解引用运算符 * · 空指针

源文件

打个比方：你在 Word 里写的那份稿子。它是给人看的文字，不是给打印机直接吃的东西。

你写程序时，先在一个纯文本文件里把你的要求一条条写下来——这个文件就是源文件。它只是一个普通的文本文件，用记事本都能打开，文件名习惯以 .cpp 结尾，比如 main.cpp。

关键的一点：它不能直接运行。就像菜谱不是菜——得有人照着做。

// 这就是源文件里的内容
#include <iostream>
int main() { return 0; }

编译

打个比方：把中文菜谱翻成厨师能直接执行的操作单。菜谱你看得懂、厨房看不懂；翻译这一步必须有人做。

计算机的处理器只认识由 0 和 1 组成的指令。你写的文字它一个字也不认识。所以需要一个专门的程序，把你的源文件翻译成机器能执行的指令——这个翻译动作就叫编译。

你用的翻译工具叫编译器（本课程用 g++）。它同时还会帮你检查错误：语法写错了、名字用错了、类型对不上，它都会拦下来告诉你。

g++ main.cpp -o first     # 让 g++ 翻译 main.cpp，产物叫 first

链接

打个比方：你写的几页纸，加上别人写好的那几页现成资料，装订成一本完整的册子。装订这一步就是链接。

一个大程序会被拆成好几个源文件分别编译。而且你的程序还会用到现成的标准库代码。把这些编译好的部分拼装成一个完整的程序，这一步叫链接。

好消息是：写代码的时候你几乎不用操心它——g++ 敲下去，编译和链接一起做完了。

可执行文件

打个比方：装订完成的那本成书。书是可以直接拿去用的，稿子不能。

链接完成后得到的产物就叫可执行文件：它可以被双击、也可以在终端里敲名字运行，这时程序才真的开始干活。

编译时用 -o 给它起名字（o 是 output 的缩写）。不起名字的话，它默认叫 a.out，容易找不到。

g++ main.cpp -o first     # 产物叫 first
./first                   # 运行它（./ 表示「当前目录下的」）

标准库

打个比方：一整套提前做好的标准零件——螺丝、齿轮、灯珠，不用你自己造，拿来就能装。

C++ 官方随编译器一起提供了一大批现成的代码：打印、读入、算数学、处理文字……都写好了。这一整套叫标准库。

用的时候要先「借」进来。借的动作就是 #include——比如 #include <iostream> 就是借进「输入输出」那一册零件。

#include <iostream>   // 借进输入输出的那批现成代码

变量

打个比方：一个贴了标签的盒子。标签就是名字，盒子里装的是会变的值。

程序要记东西，就得有个地方放。这块有名字的存储空间叫变量。名字由你起，值可以随时改——这就是它叫「变」量的原因。

盒子里装什么类型的东西，要先说清楚（见下一条）。

int score = 88;      // 一个叫 score 的盒子，装着整数 88
score = 95;          // 改成 95，盒子里原来的值被顶掉

数据类型

打个比方：盒子有不同规格。装鸡蛋的盒子和装大衣的柜子不是一回事——不仅要大小合适，还得说清「里面该放什么」。

数据类型规定三件事：这块空间能存什么、占多大、里面那串 0 和 1 该怎么解释。

课程里常用的四个：

  • int：整数，比如 88、-3；
  • double：带小数的数，比如 89.2；
  • char：单个字符，比如 'A'；
  • bool：只有真和假两个值。
int    count = 3;        // 整数
double average = 89.2;   // 小数
char   grade = 'A';      // 一个字符

运算符

打个比方：计算器上的那些按键——+、-、×。它们本身不是数，是用来「对数做动作」的。

运算符就是告诉计算机「对这些值做一个动作」的符号。除了加减乘除，还有：

  • = 是赋值（把右边的结果放进左边的盒子）；
  • == 是问相等（左右两边一样吗）；这两个千万别搞混，写错了程序不报错但结果全错；
  • % 是取余数，7 % 3 得 1；
  • <、> 是比较大小。

表达式

打个比方：一道算式。「三块钱一个，买五个多少」写下来就是 3 * 5。

由变量、数字、函数调用和运算符组成、能算出一个值的一段代码，就叫表达式。

score + 5          // 一个表达式，算出一个值
total / count      // 也是表达式

语句

打个比方：给厨房下的一条完整指令。「把鸡蛋打散」是一条，「把蛋液倒进锅里」是另一条。说完一条要停顿一下。

一条完整的、以分号结尾的指令，叫语句。程序就是按顺序执行的一条条语句。

分号在 C++ 里是「这条说完了」的标记。漏了它，编译器会报错——而且它报的位置常常在下一行，这是新手最常见的困惑。

int score = 88;              // 一条语句
cout << score << endl;        // 又一条语句

函数

打个比方：一台小机器。投料进去，它按固定流程加工，出货给你。

把一段完成特定任务的代码打包起来、起个名字，需要的时候按名字叫它干活——这就是函数。

为什么要打包？因为同一段逻辑你可能要用很多次。写一次、起个名字、到处调用，改的时候也只用改一处。

double average(double a, double b) {   // 定义一台叫 average 的机器
    return (a + b) / 2;
}

average(90, 80);                        // 用一下，得到 85

形参 / 实参

打个比方：机器上的投料口（形参，定义时留的位置）和你真正投进去的那份料（实参）。

定义函数时写的、用来接收数据的占位名字，叫形参；调用时真正传进去的值，叫实参。

为什么非要分两个词？因为「改的到底是哪一个」这件事，后面会让你踩坑。只说「参数」两个字，说不清。

double average(double a, double b) { ... }
//             ^^^^^^^^^^^^^^^^^^^^ 形参：位置

average(90, 80);
//      ^^^^^^^ 实参：真正投进去的值

返回值

打个比方：机器出货口交出来的那个成品。

函数干完活，交回给调用者的那个结果，叫返回值，用 return 交回。上面的 average(90, 80) 返回值是 85。

有些函数不交出东西（只是打印点什么），那种函数用 void 声明。

值传递

打个比方：你把文件复印一份交给同事。他在复印件上乱涂，你手里那份原件一个字都没变。

C++ 调用函数时默认就是这样：函数拿到的是实参的副本，不是原件。所以函数里改来改去，调用方的变量一点没动。

这解释了很多人的第一个「玄学 bug」：明明在函数里把成绩改成了满分，回到 main 一打印，还是原来的分数。想真改到外面的数据，得用指针——这就是后面几章要解决的问题。

作用域

打个比方：一把钥匙能开哪几扇门。出了那个范围，这把钥匙就不管用了。

一个名字（变量、函数）在源代码里「能被用到」的范围，叫作用域。C++ 里最基本的边界是一对花括号 { }：花括号里定义的变量，出了这对括号就不认识了。

它是「写代码时」的规矩（编译期就定了），和「程序运行时变量活多久」是两件事——那是下一条。

{
    int score = 88;     // 这个 score 只活在这对括号里
}
cout << score;          // 出了括号，编译器说：score 是谁？

变量生命周期

打个比方：一盆花的花期。什么时候种下、什么时候谢掉，这是「它存在多久」；而上一条讲的是「它的名字在哪里能被叫到」。两件事容易混，但确实不是一回事。

局部变量在自己的定义处被创建，在它所在的那对花括号结束时被销毁。这段「活着的时长」叫变量生命周期。

会踩的坑：函数里定义的变量，函数一返回就没了。你要是把一个指向它的地址带回外面用，那块地方可能已经被别人占用了。

数组

打个比方：一排连着的储物柜，共用一块编号牌。你说「3 号柜」，大家就知道是哪一个。

把同一类型的多个值排成一排连续存放、共用一个名字、用下标区分——这就是数组。

适合的场景很明确：一个班的成绩。你不想开三十个变量（score1、score2……），而数组配循环正好干这个。

int scores[5] = {88, 76, 95, 60, 82};
//  scores[0] 是 88，scores[1] 是 76 …… 共 5 个

下标

打个比方：柜子上的编号。

数组元素的位置编号叫下标。C++ 里下标从 0 开始数——这一点最容易记错。

「5 个元素的数组，下标是 0 到 4」。写 scores[5] 不是第 5 个，而是越界了：它会去读一块不属于你的地方，程序可能算出莫名其妙的数，甚至直接崩掉，而且不一定报错。这是新手很常踩的坑。

C 风格字符串

打个比方：一列排队的人，队尾站着一个举牌子的（举着「到此为止」）。没有那个牌子，别人就不知道队到哪儿算完。

一串字符要有地方放，C++ 里最原始的做法是用字符数组存，并在末尾放一个特殊字符 '\0' 当结束标记。这种以 '\0' 结尾的一串字符，叫C 风格字符串。

那个 '\0' 不是给你看的，是给程序看的：它顺着从前往后读，读到 '\0' 才知道「完了」。

char name[6] = "Zhang";   // 5 个字母 + 末尾自动补一个 '\0'，所以至少要开 6 格
//   下标: 0 1 2 3 4  5
//   内容: Z h a n g \0

内存地址

打个比方：门牌号。你朋友住在哪，说的是「几号楼几零几」，不是把房子搬给你。

内存里每个字节都有一个编号，这个编号就是内存地址。变量就住在某个地址上。

平时你不需要关心它——用变量名就行，编译器会替你翻译成地址。但学指针时，这个「门牌号」就成了主角。地址长得像 0x16f5a3b8c，每次运行都可能不一样，这是正常的。

指针

打个比方：一张写着门牌号的纸条。纸条上写的是「3 号楼 502」，纸条本身不是房子——它只是告诉你房子在哪。

一个专门用来存内存地址的变量，叫指针。它的值是地址，不是那个地址上的数据。

这是全课程最难也最关键的一节。很多人卡在这里，往往是因为没分清两件事：纸条（指针本身）和纸条上写的门牌号指向的那间屋子（那个地址上的数据）。下一章会用图反复讲这个区别。

int score = 88;
int *p = &score;   // p 是一张纸条，上面写着 score 的地址

取地址运算符 &

打个比方：问门牌号。「你家住哪儿？」——得到一个编号，不是得到你家。

写在变量前面，得到这个变量所在的内存地址。读作「取 score 的地址」。

&score        // score 的地址，比如 0x16f5a3b8c

解引用运算符 *

打个比方：照着纸条上的门牌号找过去，打开门，看屋里有什么（或者往里放东西）。

写在指针前面，表示「顺着这个地址，去访问那个地址上的数据」。读作「解引用 p」。

注意 * 这个符号有两种身份：写在类型后面是「这是个指针」，写在指针前面是「去那个地址看看」。靠位置区分。

int score = 88;
int *p = &score;    // 这里的 * 表示 p 是指针
cout << *p;         // 这里的 * 表示「去 p 指的地址取数据」，印出 88

*p = 100;           // 也可以反过来往里写：score 变成 100 了

空指针

打个比方：一张什么都没写的纸条。它明明白白告诉你「我没指向任何地方」——比一张写着乱码的纸条安全得多。

值为 0、写作 nullptr 的指针，叫空指针，表示「不指向任何有效对象」。

它是「故意留空」的一种约定，用之前先判断一下，程序就不会踩到不该碰的内存。

int *p = nullptr;             // 明确表示：现在不指向任何地方

if (p != nullptr) {
    cout << *p;               // 确认有指向才去读，安全
}
