0009 · 作用域与值传递

作用域与值传递

本节目标：说清「在函数里改了变量、回到 main 却没变」的原因，并能判断一段调用之后调用方的变量会是多少。

改了没变的成绩

上一章我们把求平均包成了函数，效果不错。顺着同样的想法，很自然会写出这样一个函数：把一份不及格的成绩改成满分。

想法很清楚：传给函数一份成绩，函数里把它改成 100。存成 scope-01.cpp 再编译：

// scope-01.cpp -- 现象：在函数里改成满分，回到 main 打印还是原来的分数
#include <iostream>
using namespace std;

void makeFull(int score)          // 想把这份成绩改成满分
{
    score = 100;
    cout << "函数里看到的成绩：" << score << endl;
}

int main()
{
    int score = 58;
    makeFull(score);
    cout << "回到 main 看到的成绩：" << score << endl;
    return 0;
}
$ g++ scope-01.cpp -o scope-01
$ ./scope-01
函数里看到的成绩：100
回到 main 看到的成绩：58

函数里那个 score 明明被改成了 100，回到 main 一打印，还是 58。更让人不放心的是，编译器一声不响。这就是很多人写程序时遇到的第一个「玄学 bug」。

它一点也不玄。要解释它，需要两个词：作用域与值传递。

作用域：名字的范围

先看一个更容易察觉的事实：函数里写的名字，出了这个函数就不认得。makeFull 里的 score、上一章 loops-03.cpp 里的 sum 与 count，都只在各自的函数里有效。

作用域：一个名字（变量、函数）在源代码里能被用到的范围；{} 花括号是 C++ 里最基本的范围分界。

为什么需要这个词：一份程序里的名字很多，i、sum、score 这种短名字会被反复使用。要说清「这个 score 指的是哪一块存储空间」，就得先能说出名字的有效范围。有了作用域，两个函数里可以各写一个 sum，它们互不干扰；同一个函数里写了两个同名的变量，编译器反而会报错。

作用域是看代码得出的范围：读到哪一行，哪些名字能用，是写代码时就定下来的。

局部变量与全局变量

按声明的位置，变量分两种。

局部变量：在函数或花括号里面声明的变量，它的作用域就是声明它的那一段。 全局变量：写在所有函数外面的变量，它的作用域是从声明处往下的所有函数。

先看两个函数里的同名局部变量。存成 scope-02.cpp 再编译：

// scope-02.cpp -- 两个函数里的同名变量，是两份互不相干的内存
#include <iostream>
using namespace std;

void report();
void adjust();

int main()
{
    report();
    adjust();
    return 0;
}

void report()
{
    int total = 90 + 85;                    // report 自己的 total
    cout << "report 里的 total：" << total << endl;
}

void adjust()
{
    int total = 10;                         // adjust 自己的 total
    cout << "adjust 里的 total：" << total << endl;
}
$ g++ scope-02.cpp -o scope-02
$ ./scope-02
report 里的 total：175
adjust 里的 total：10

两个函数各写了一个 total，各用各的，谁也不影响谁。它们同名，却住在两块不同的存储空间里。

全局变量则可以跨函数访问。存成 scope-04.cpp 再编译：

// scope-04.cpp -- 全局变量，以及同名的局部变量把它挡住
#include <iostream>
using namespace std;

int fullScore = 100;            // 写在所有函数外面：全局变量

void printFull()
{
    int fullScore = 150;        // 本函数自己的同名局部变量
    cout << "函数里看到的满分：" << fullScore << endl;
}

int main()
{
    printFull();
    cout << "main 里看到的满分：" << fullScore << endl;
    return 0;
}
$ g++ scope-04.cpp -o scope-04
$ ./scope-04
函数里看到的满分：150
main 里看到的满分：100
同名变量的遮挡

printFull 里打印出来的是 150，因为函数内部的局部变量 fullScore 遮住了同名的全局变量：在函数里面，就近的那个名字生效。

这种遮挡很难看出问题在哪，尤其是几年后再读到这份代码。全局变量能不用就不用——它的值可能被任何一个函数改掉，出问题时无从下手。这一条也是很多团队代码规范里明确禁止全局变量的原因。

值传递：改的是副本

回到开头那个没改动的成绩。现在可以解释它了。

值传递：C++ 调用函数时的默认传参方式：函数拿到的是实参的副本，函数里改动副本不影响原来的变量。

为什么需要这个词：调用一个函数时，实参的值要交到函数里的形参手上。交的方式有两种可能——把原件的地址告诉它，或者复制一份给它。C++ 默认是复制一份。这件事决定了「函数里改了形参，外面会不会跟着变」，所以需要一个专门的说法把它讲明白。

调用 makeFull(score) 的那一刻，发生的是这样几件事：

  1. main 里的实参 score 值是 58；
  2. 函数里的形参 score 是一块新的存储空间，58 被复制进去；
  3. 函数体里的 score = 100; 改的是这块新空间；
  4. 函数返回，这块新空间连同它的名字一起消失；
  5. main 里那个 score 从头到尾没被碰过，还是 58。

所以 makeFull 这个名字起得有些乐观：它把副本改成了满分，原件还在原处。

变量的生命周期

作用域说的是「名字在代码的哪一段能被用到」，还有另一件事：这块存储在程序运行的哪一段时间里存在。这件事叫生命周期。

生命周期：一个变量从被创建出来、到被回收掉的这段时间。这个概念在别的书里也叫生存期，本课程统一说生命周期。

为什么需要这个词：局部变量不是程序一开始就全都准备好了。局部变量在自己的定义处被创建，在它所在的那对花括号结束时被回收；函数里的局部变量，寿命就在这一次调用之内。理解这一点，才能解释「为什么两次调用之间，局部变量的值留不下来」。

存成 scope-05.cpp 再编译：

// scope-05.cpp -- 局部变量的寿命：每次调用都重新出生一次
#include <iostream>
using namespace std;

void countCall()
{
    int count = 0;              // 每次进入函数都重新声明、重新赋 0
    count++;
    cout << "这一次调用看到的 count：" << count << endl;
}

int main()
{
    countCall();
    countCall();
    countCall();
    return 0;
}
$ g++ scope-05.cpp -o scope-05
$ ./scope-05
这一次调用看到的 count：1
这一次调用看到的 count：1
这一次调用看到的 count：1

三次调用都打印 1。count++ 明明把值加到了 1，可下一次调用走进来，int count = 0; 又执行了一遍：上一轮那块存储已经随函数返回被回收，这一轮拿到的是新的一块，值从 0 开始。

因此 countCall 并不具备「记录调用了几次」的能力。要让一个值跨过函数返回活下来，得换一种存储方式，这不在本课程范围内。

花括号就是范围

作用域的边界就是花括号。在花括号里声明的变量，出了这对花括号就不认得。存成 scope-03.cpp：

// scope-03.cpp -- 反例：在花括号里声明的变量，出了花括号就不认识了
#include <iostream>
using namespace std;

int main()
{
    {
        int temp = 60;          // temp 的作用域就是这个花括号
    }

    cout << temp << endl;       // 编译错误：这里已经看不见 temp
    return 0;
}
出了花括号就不认得这个名字

编译这个文件，编译器会指着第 11 行报错：

$ g++ scope-03.cpp -o scope-03
scope-03.cpp:11:13: error: use of undeclared identifier 'temp'

temp 声明在里面那对花括号里，那对花括号一结束，这个名字就不存在了。把 int temp = 60; 挪到外面那层，或者在花括号里把要用的活儿干完，都能解决。

编译器还会顺带提醒一句 warning: unused variable 'temp'，意思是这个变量声明了却没人用——在这个例子里，它正好提示了 temp 的作用域太窄。

要让函数真改到外面

回到开头那个函数。「在函数里改，外面没变」的根源，是函数手里只有一份副本。

要让函数真改到调用方的变量，得先能说出这个变量住在内存的哪个位置，再让函数拿着这个位置去改原来那份。这套东西要到后面「内存地址与取地址符」那一课才讲，这里先不展开，只留一句话——函数拿不到原件的时候，就只能改副本。

动手做：把现象跑出来

这一节的知识点都是「解释现象」，动手的方式就是把现象跑出来、再动一动看结论变不变。

练习 四步跑出「改了没变」

第 1 步 · 看清现象。编译运行 scope-01.cpp，对照两行输出：函数里是 100，main 里是 58。

第 2 步 · 看清执行顺序。在 makeFull 里 score = 100; 之后加一行 cout << "改完了" << endl;，在 main 里 makeFull(score); 后面也加一行 cout << "回到 main" << endl;，运行，从这两行输出的先后确认「先进函数、再回 main」的顺序。

第 3 步 · 改个名字。把 makeFull 的形参从 int score 改成 int s，函数体里相应改成 s = 100;，重新编译运行。输出不变——改的是副本，副本叫什么名字都一样。

第 4 步 · 删掉遮挡的那一行。把 scope-04.cpp 里 printFull 的 int fullScore = 150; 删掉，重新编译运行。这一次函数里读到的是全局变量的 100，两次打印变成一样的值。
