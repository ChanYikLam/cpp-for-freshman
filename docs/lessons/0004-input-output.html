让用户把数据敲进来

本节目标：写出一个能读入 3 个成绩、自己算出并打印平均分的完整程序。

这一课是主线项目的起点

前面三课的成绩都是写死在代码里的，换一个人的分数就得改代码再编译一次。成绩管理系统要能对着一群学生用，第一步就是让程序自己开口问、自己听得见回答。

程序得能开口

先把「写死」这件事看清楚。存成 io-06.cpp 编译运行：

#include <iostream>

using namespace std;
int main()
{
    cout << "请输入三门课的成绩：";

    int score1 = 0;
    int score2 = 0;
    int score3 = 0;
    cin >> score1 >> score2 >> score3;

    double average = (score1 + score2 + score3) / 3;

    cout << endl;
    cout << "平均分：" << average << endl;

    return 0;
}

这份程序读进来了三个成绩，但平均分那一行又踩了整数除法的坑。它是这一课的反面教材，也是「改造」那道题的目标。

流：为什么叫「输入输出流」

要让程序从键盘拿数据，得先有一个「数据从哪里来、往哪里去」的模型。C++ 用的模型是流（stream）：把数据看成一串按顺序流动的字符。

  • 输入流：从键盘流向程序的一串字符。你在终端敲 92 88 87 再回车，这 8 个字符就按输入流的方向进到程序里。
  • 输出流：从程序流向终端的一串字符。程序打印的每个字都往这个方向走。

这个模型解决了一个实际问题：程序不用关心数据具体是从键盘、还是从一个文件、还是从网络来的——它只管从一个「输入流」里往外取。取到一个流对象，就等于接通了数据来源。

C++ 提供了两个现成的流对象，都在 <iostream> 里：

对象方向用途
cout程序 → 终端输出，前面几课一直在用
cin终端 → 程序输入，这一课的主角

iostream 这个名字就是 input-output stream 的缩写。cout 的 c 是 console（控制台），cin 的 c 是 character（字符）——它按字符往外取。

两个运算符的方向很容易记反，因为刚学时脑子里想的是「取」和「印」。记不住的时候看箭头的尖：箭头从数据出发，指向要去的地方。

接着看那两个运算符。<< 和 >> 的形状是有讲究的：箭头指向哪边，数据就往哪边流。

把两个箭头写反，编译器一次全给你挑出来

初学最常出的错就是把 >> 写成 <<。存成 broken-io-01.cpp 就长这样：

#include <iostream>

using namespace std;
int main()
{
    int score = 0;
    cout << "请输入成绩：";
    cin << score;
    return 0;
}
broken-io-01.cpp:7:14: error: invalid operands to binary expression ('istream' (aka 'basic_istream<char>') and 'int')
    7 |     cin << score;
      |     ~~~~~~~~ ^  ~~~~~

这一行的读法是：<< 左边应该是 ostream（输出流）一类的对象，可你给它的是 istream（输入流）。看括号里那两个字就够了——istream 和 ostream 差一个字母，含义完全不同：「往输出流里插」和「从输入流里取」是两件事。

cout > "..." 这种写反的半边也一样会被拦下：

broken-io-02.cpp:6:15: error: invalid operands to binary expression ('ostream' (aka 'basic_ostream<char>') and 'const char[19]')
    6 |     cout > "请输入成绩：";
      |               ^ ~~~~~~~~~~~~~~

第一次读入

写法就是把 cout 那套反过来。存成 io-01.cpp，编译运行，然后在终端里敲一个数：

#include <iostream>

using namespace std;
int main()
{
    int score = 0;

    cout << "请输入一个成绩：";
    cin >> score;
    cout << "你输入的成绩是 " << score << endl;

    return 0;
}
$ ./io-01
请输入一个成绩：88
你输入的成绩是 88

三行代码各自负责一件事，缺一件就出问题：

  1. cout << "请输入一个成绩："; 是输入提示语。它不参与计算，作用只是告诉屏幕前的人「现在该你了」。
  2. cin >> score; 从输入流取一个值放进 score。取不到东西，程序就在这里等。
  3. 第三行把读到的值打印出来，让你确认读到的和你敲的是同一个。
忘记写提示语，看起来就像死机

cin >> score; 执行时会一直等，直到输入流里来了数据。如果前面没有提示语，屏幕上就是一个静止的光标，敲键盘也没反应（因为字符还在缓冲区里、要按回车才送出去）。用户会以为程序卡死了。

写输入代码的规矩：每一个 cin 前面配一句提示语，并且提示语要说清要输入的是什么、什么格式。"请输入一个成绩：" 比 "请输入：" 有用得多。

一次读多个值

成绩有三个，可以连着读。存成 io-03.cpp：

#include <iostream>

using namespace std;
int main()
{
    int age = 0;
    char grade = ' ';

    cout << "请输入年龄：";
    cin >> age;
    cout << "请输入等级（A/B/C）：";
    cin >> grade;
    cout << "年龄：" << age << "，等级：" << grade << endl;

    return 0;
}
$ ./io-03
请输入年龄：18
请输入等级（A/B/C）：B
年龄：18，等级：B

也可以用一条语句连读多个：cin >> score1 >> score2 >> score3;。>> 是从左往右依次执行的，效果和写三行一样。

空格分隔是这里要掌握的一件实事：cin >> 取一个值时，会先自动跳过前面所有的空格、制表符和换行符，然后一直取到下一个空白为止。所以下面三种输入，程序读到的三个数完全相同：

92 88 87
92
88
87
   92    88
87

判断的边界是空白。这个性质让你不用操心用户是按空格还是按回车分的——但第 6 课会看到，它在另一种场景下也会带来麻烦。

主线项目：三门成绩算平均分

现在把这一课的东西拼成完整的程序。存成 io-02.cpp：

#include <iostream>
#include <iomanip>

using namespace std;
int main()
{
    const int kSubjectCount = 3;

    cout << "请输入三门课的成绩（用空格或回车分开）：";

    double score1 = 0.0;
    double score2 = 0.0;
    double score3 = 0.0;
    cin >> score1 >> score2 >> score3;

    double total = score1 + score2 + score3;
    double average = total / kSubjectCount;

    cout << fixed << setprecision(1);
    cout << endl;
    cout << "三门成绩：" << score1 << "、" << score2 << "、" << score3 << endl;
    cout << "总分：" << total << endl;
    cout << "平均分：" << average << endl;

    return 0;
}
$ ./io-02
请输入三门课的成绩（用空格或回车分开）：92 88 87.5

三门成绩：92.0、88.0、87.5
总分：267.5
平均分：89.2

这个程序里有四处设计决定，每一处都有理由：

  • 三个成绩声明成 double。成绩本身可能是 87.5，用 int 会在读入那一步就把小数切掉。
  • const int kSubjectCount = 3;。科目数只有一处定义，以后要改成五门就改这一行。
  • total / kSubjectCount 里两个操作数一个是 double：kSubjectCount 是 int，但 total 是 double，所以走的是小数除法——上一课那条规则的直接应用。
  • 输出对齐用两行：cout << fixed << setprecision(1); 是输出格式控制，<iomanip> 是它所在的头文件。

第三条里的 setprecision(1) 是「小数点后保留 1 位」；fixed 是「用定点表示法，不要自己切换成科学计数法」。两者要一起用，只写 setprecision 在某些值上会变成有效位数，而不是小数位数。fixed 会一直生效到你改回来为止，所以上面那行只写一次，后面所有 cout 都按这个格式印——注意它连 score1 都影响到了，所以 92 印成了 92.0。

为什么要给小数定精度

double 打印 267.5 / 3 这种除不尽的值时，默认会印出一串很长的小数。成绩单上不需要 15 位小数，一位就够。setprecision(1) 管的就是这件事：控制显示，不改变存的值。算的时候仍然是完整的 double，只是印出来的时候按你的要求裁。

输入失败：cin 会坏掉

读输入有一件必须提前知道的事：用户可能敲进来的东西不是数字。

存成 io-04.cpp 试试，输入 90 abc 80：

#include <iostream>
#include <iomanip>

using namespace std;
int main()
{
    cout << "请输入三个成绩：";

    double score1 = 0.0;
    double score2 = 0.0;
    double score3 = 0.0;
    cin >> score1 >> score2 >> score3;

    cout << "读到的三个数：" << score1 << " " << score2 << " " << score3 << endl;
    cout << "输入是否成功：" << boolalpha << static_cast<bool>(cin) << endl;

    return 0;
}
$ ./io-04
请输入三个成绩：90 abc 80
读到的三个数：90 0 0
输入是否成功：false

第一个数读到了 90，后面两个都是 0，最后一行说输入失败了。经典教材里把这一刻发生的事情列成四条，每条都要记住：

  • score2 的值保持不变——它没被写成什么奇怪的东西，abc 这个值根本没有进到它里面；
  • 不匹配的输入留在输入队列里没被取走，abc 还在那儿；
  • cin 对象内部被设置了一个错误标记；
  • 之后所有对 cin 的读取全部失败，包括后面本来要读的 score3。

最后一条是最坑的地方：一次输入失败会让 cin 从此进入失败状态，后面读什么都读不到，而这一行 abc 还赖在队列里。所以失败之后不能直接再读，必须先做两件事：

cin.clear();
cin.ignore(1000, '\n');

clear() 清掉那个错误标记，让 cin 重新可用——这一步与数组、与指针都无关，就是「把错误状态复位」。ignore(1000, '\n') 是「从队列里丢掉字符」，最多丢 1000 个，或者丢到遇见换行符为止——这一步是把赖在队列里的 abc 清出去。

存成 io-05.cpp，看恢复过程：

#include <iostream>

using namespace std;
int main()
{
    int score = 0;

    cout << "请输入成绩：";
    cin >> score;

    if (cin.fail())
    {
        cout << "\n这一段不是数字，读入失败了。丢弃这一行，重新读一次。\n";
        cin.clear();
        cin.ignore(1000, '\n');

        cout << "请重新输入成绩：";
        cin >> score;
    }

    cout << "最终读到：" << score << endl;

    return 0;
}
$ ./io-05
请输入成绩：abc
这一段不是数字，读入失败了。丢弃这一行，重新读一次。
请重新输入成绩：90
最终读到：90

这份程序里新出现了 if (...) 和一对花括号。它们是「如果……就……」的写法，里面那段就是「如果读失败了才做」。第 6 课会把 if 完整讲一遍，这里先用着——它的意思从字面上就能读出来。

动手做

上手做 第 1 步 · 把写死的成绩变成读进来的

把开头那份 io-06.cpp 改对。要求：读入三个成绩，打印平均分，并且平均分要有小数。改完之后用 92 88 88 和 92 88 87.5 各跑一次，看两次的结果差别。

这一步的验收标准是：输入 92 88 87.5 时，平均分那一行印出来的数和按计算器算出来的一致。

上手做 第 2 步 · 补上提示语与格式

在上一份程序上补两件事：

  • 每个 cin 前面都要有提示语，说清要输入什么、怎么分隔；
  • 用 fixed 与 setprecision(1) 把平均分印成小数一位。

补完之后，输入 92 88 87.5 应该看到这样：

$ ./io-06
请输入三门课的成绩（用空格或回车分开）：92 88 87.5
平均分：89.2

再故意试一次「不写提示语」：把提示语那一行删掉，编译运行，屏幕上就只剩光标在那里等着——用户不知道程序要什么，也不知道该敲几位数。这就是用户以为程序死机的现场。

上手做 第 3 步 · 让程序扛住乱输入

先看现在的程序读到 abc 会怎样。io-04.cpp 是专门用来看这件事的一份：它读三个 double，然后把读到的值和输入是否成功都打印出来。存成自己的一份，编译运行，敲 abc 88 87：

g++ io-04.cpp -o io-04 && ./io-04
$ ./io-04
请输入三个成绩：abc 88 87
读到的三个数：0 0 0
输入是否成功：false

三个格子一个都没读到——第一个值就读失败了，后面的连试都不试，三个都还是声明时的初值 0。最后一行 false 是 cin 自己被转成布尔值之后的样子，它说明 cin 已经进了失败状态：从这里往后，所有的 cin 读取都会失败。

这就是问题的全貌，也是第 4 课那个 clear() 与 ignore() 的用处。按 io-05.cpp 的样子加上那两行，让程序在读到非数字之后重新问你一次：

g++ io-05.cpp -o io-05 && ./io-05
$ ./io-05
请输入成绩：abc
这一段不是数字，读入失败了。丢弃这一行，重新读一次。
请重新输入成绩：90
最终读到：90

这一步就是成绩管理系统第一次变得能用的地方：一个同学敲错了分数，程序不会一路错到底。

上手做 第 4 步 · 完整交付

把前三步合成一个程序：连读三个成绩、算总分与平均分、输出对齐、读入失败能重来。编译通过之后，用下面三组输入各跑一次，把输出抄下来：

92 88 87.5
92
88
87
abc
92 88 87.5

第三组会走一次失败重读的路径。跑到这里，这个程序已经能交给人用了。
