字符数组与字符串函数

本节目标：用字符数组存下姓名，用 strcmp 判断两个姓名是否相同

成绩表上光有分数不够，还得知道这份分数是谁的。姓名在 C++ 里是一串字符，这一课要把它存进数组，并让程序能比较两个姓名。

上一课的数组装的是数字，一个下标对一个数，各占各的格子。姓名不一样：它是一串有先后顺序的字符，第一个字是什么、第二个字是什么都有意义。这一课要解决的就是「怎么把一串字符放进数组」，以及随之而来的几个坑。

一串字符在内存里长什么样

先看看字符数组和上一课的数字数组有什么不同。

存成一个字符数组，最直白的办法是把每个字符分别写进数组的每一格：

存成 cstr-01.cpp 再编译：

char name1[8] = {'L', 'i', 'u', '\0'};

char 是专门存一个字符的数据类型，'L' 是字符常量，用一个字符占一格。到第 8 格为止，前 3 格装了 L、i、u，第 4 格装的是 '\0'。'\0' 读作「空字符」，它的编码值是 0，在 C++ 里专门用来标记「这一串字符到这里就完了」。

这一串字符加上末尾的空字符，就是 C++ 里的字符串。字符串并不要求你把整张表填满，name1 有 8 格，只用掉 4 格，剩下 4 格里是什么没人关心，后面的函数看到 '\0' 就停。

一格一格地列字符太啰嗦，还得自己记住末尾那个 '\0'。C++ 允许直接用双引号里的字符串给字符数组初始化，编译器会把空字符自动补在末尾：

char name2[8] = "Zhang";

"Zhang" 是字符串常量，它本身就已经带着末尾的空字符。这里数组开了 8 格，只用了 6 格（5 个字母加 1 个空字符）。

双引号和单引号在这里是两件东西：'L' 是一个字符，"L" 是一个字符串（L 加上空字符）。两者互换会编译不过，编译器会告诉你类型对不上。

把两个数组都打印出来看一眼。

存成 cstr-01.cpp 再编译：

// cstr-01.cpp -- 字符数组是怎么存一串字符的
#include <iostream>
#include <cstring>          // strlen 声明在这个头文件里
using namespace std;

int main()
{
    // 写法一：一个一个字符地列出来，最后一个必须是 '\0'
    char name1[8] = {'L', 'i', 'u', '\0'};

    // 写法二：直接用双引号里的字符串初始化，'\0' 由编译器自动补在末尾
    char name2[8] = "Zhang";

    cout << "名字一：" << name1 << endl;
    cout << "名字二：" << name2 << endl;

    cout << "name1 里装了 " << sizeof(name1) << " 字节" << endl;
    cout << "name1 这个名字有 " << strlen(name1) << " 个字符" << endl;

    cout << "name2 里装了 " << sizeof(name2) << " 字节" << endl;
    cout << "name2 这个名字有 " << strlen(name2) << " 个字符" << endl;

    return 0;
}
$ g++ cstr-01.cpp -o cstr-01
$ ./cstr-01
名字一：Liu
名字二：Zhang
name1 里装了 8 字节
name1 这个名字有 3 个字符
name2 里装了 8 字节
name2 这个名字有 5 个字符

用 cout 打印一个字符数组，它会连着往下打印，直到遇见空字符为止。这正是空字符存在的意义：数组有多长不重要，cout 只需要知道在哪里停下。

strlen 与 sizeof 差在哪里

上一课用 sizeof 量过数组占多少字节，那是整个数组的大小。处理字符串时更常问的是另一个问题：这串字符有几个字符？

这个问题由 strlen 回答。strlen 从数组的第一个格子开始数，数到空字符前面那一格为止，把数出来的个数交回给你。空字符本身不算在内。

于是同一个数组会有两个数字，含义完全不同：

问法写法对 name1 的结果对 name2 的结果
这个数组占多少格sizeof(name1)88
这串字符有几个字符strlen(name1)35
数组开大一点没坏处

处理字符串的函数都是按空字符停下来的，不看数组有多长，所以数组开得比名字长只是浪费几格，不会出错。真正要小心的是反过来：数组开得刚好够放名字，却忘了给空字符留一格。

char name[5] = "Zhang"; 会编译不过——5 个字母加 1 个空字符一共需要 6 格。这个错编译器能替你抓住，属于运气好的那一类。

拷贝与比较：两个必须用函数的动作

字符串有两个日常动作，用 = 和 == 都做不成，必须调用函数。

先说比较。两个姓名是不是同一个人，直觉上应该写 nameA == nameB。数组名在 C++ 里代表的是「这个数组住在哪里」，所以 == 比较的是两个数组各自的住址，跟里面装的名字一个字都没关系。两个内容完全一样的姓名，住址不同，== 也会说它们不同。

比较内容要用 strcmp（string compare 的缩写）。它接收两个字符数组，逐格比较字符，然后交回一个整数：

strcmp(a, b) 的返回值含义
0两串字符完全相同
正数a 排在 b 后面（按字符编码顺序）
负数a 排在 b 前面

所以判断两个姓名相同，写 strcmp(a, b) == 0。

存成 cstr-03.cpp 再编译：

// cstr-03.cpp -- 比较两个姓名：为什么 == 不管用，strcmp 怎么用
#include <iostream>
#include <cstring>          // strcmp 声明在这个头文件里
using namespace std;

int main()
{
    char a[8] = "Zhang";
    char b[8] = "Zhang";
    char c[8] = "Liu";

    if (a == b)                       // 比的是两个数组各自的地址
        cout << "a == b 说：两个名字相同" << endl;
    else
        cout << "a == b 说：两个名字不同（其实内容是一样的）" << endl;

    if (strcmp(a, b) == 0)            // 比的是逐个字符的内容
        cout << "strcmp(a, b) 说：两个名字相同" << endl;
    else
        cout << "strcmp(a, b) 说：两个名字不同" << endl;

    if (strcmp(a, c) != 0)
        cout << "strcmp(a, c) 说：两个名字不同" << endl;

    cout << "strcmp(a, c) 返回 " << strcmp(a, c) << "（正数表示 a 排在 c 后面）" << endl;
    cout << "strcmp(c, a) 返回 " << strcmp(c, a) << "（负数表示 c 排在 a 前面）" << endl;

    return 0;
}
$ g++ cstr-03.cpp -o cstr-03
$ ./cstr-03
a == b 说：两个名字不同（其实内容是一样的）
strcmp(a, b) 说：两个名字相同
strcmp(a, c) 说：两个名字不同
strcmp(a, c) 返回 14（正数表示 a 排在 c 后面）
strcmp(c, a) 返回 -14（负数表示 c 排在 a 前面）

strcmp 交回的具体数字不用记，只需要记它的符号：0 就是相同，非 0 就是不同。前面的 14 是两个首字符编码的差，换个编译器或换一对姓名，这个数会变，你只要判断它是不是 0。

编译器其实提醒过你

写 if (a == b) 时，编译器会打一行警告：array comparison always evaluates to false。它知道两个不同的数组地址不会相等，所以这个条件恒为假。警告不是错误，程序照样编译出来，但这类警告值得停下来看一眼。

第二个动作是拷贝。数组名不能直接赋值，nameA = nameB 会编译报错，因为数组名不是可以改的东西。要把一个名字搬到另一个数组里，用 strcpy（string copy）：

存成 cstr-02.cpp 再编译：

// cstr-02.cpp -- 数组不够大时，拷贝会把名字截断
#include <iostream>
#include <cstring>          // strncpy、strlen 声明在这个头文件里
using namespace std;

int main()
{
    char name[6];           // 最多装 5 个字符，剩下的那 1 格留给 '\0'

    // 用备份来接收从别处拷过来的名字：最多拷 5 个字符，不写 '\0'
    strncpy(name, "Zhang", 5);
    name[5] = '\0';         // 自己补上结尾标记，这一格刚好是数组的最后一格

    cout << "拷贝后的名字：" << name << endl;
    cout << "它占了多少格：" << strlen(name) << endl;

    // 如果来的名字更长，多出来的部分会被丢掉，数组里不会多塞东西
    char shortName[6];
    strncpy(shortName, "ZhangSan", 5);
    shortName[5] = '\0';

    cout << "更长名字存进来只剩：" << shortName << endl;

    return 0;
}
$ g++ cstr-02.cpp -o cstr-02
$ ./cstr-02
拷贝后的名字：Zhang
它占了多少格：5
更长名字存进来只剩：Zhang

这里用的是带 n 的版本 strncpy，它多收一个数字：最多拷几个字符。它不会替你在末尾补空字符——strncpy(dest, src, n) 拷贝完 n 个字符就交差，补 '\0' 是调用方自己的事。所以 name[5] = '\0'; 这一句不能省，它把最后一格指定成空字符，字符串才算完整。

名字比数组长的时候

strcpy 只看源字符串的空字符在哪，不管目标数组有多大。如果名字比数组长，多出来的字符会被写到数组外面去，把旁边的变量悄悄改掉。

char name[6]; strcpy(name, "ZhangSan"); 就是这个情形。编译器会给出提示：'strcpy' will always overflow; destination buffer has size 6, but the source string has length 9。这类提示值得当成错误来看——它指出的正是后面会看到的那种「运行着运行着别处的数据变了」的怪事。

字符串函数都在 cstring 里

strlen、strcpy、strncpy、strcmp 都是标准库函数，声明在 <cstring> 这个头文件里。用到哪个，就在文件开头 #include <cstring>。漏了这一行，编译器会说找不到这个名字。

让成绩表带上姓名

现在把姓名接到成绩管理系统上。一张表存分数，另一张表存姓名，两张表用同一个下标对齐：names[i] 的分数就是 scores[i]。

存成 cstr-04.cpp 再编译：

// cstr-04.cpp -- 成绩表带上"谁"：姓名表与分数表用同一个下标对齐
#include <iostream>
#include <cstring>
using namespace std;

int main()
{
    char names[4][10] = {"Zhang", "Liu", "Chen", "Wang"};
    int  scores[4]    = {88, 76, 95, 60};
    int n = 4;

    cout << "成绩表：" << endl;
    for (int i = 0; i < n; i++)
        cout << "  " << names[i] << "  " << scores[i] << " 分" << endl;

    // 找一个人：把所有姓名挨个比一遍
    char who[10] = "Chen";
    int found = -1;                     // 约定 -1 表示没找到
    for (int i = 0; i < n; i++)
        if (strcmp(names[i], who) == 0)
            found = i;

    if (found >= 0)
        cout << who << " 的成绩是 " << scores[found] << " 分" << endl;
    else
        cout << "表里没有 " << who << endl;

    return 0;
}
$ g++ cstr-04.cpp -o cstr-04
$ ./cstr-04
成绩表：
  Zhang  88 分
  Liu  76 分
  Chen  95 分
  Wang  60 分
Chen 的成绩是 95 分

char names[4][10] 是二维字符数组，可以读成「4 行，每行 10 格」：4 个姓名，每个姓名最多占 9 个字符加 1 个空字符。names[i] 取出来的就是第 i 行那个字符数组，可以直接交给 strcmp 和 cout。

存成 cstr-04.cpp 再编译。动手之前先把上面这段自己敲一遍：把 who 改成表里没有的姓名，看程序走的是哪条分支；再把某个姓名改长一点，看看 10 格够不够。
