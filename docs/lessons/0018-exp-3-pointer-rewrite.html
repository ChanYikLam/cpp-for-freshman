实验三：用指针改写核心操作

本节目标：用指针版函数算出平均分、最高分并排好序，结果与下标版完全一致，程序不因空指针与越界而崩溃。

这一课是终点验收

最后一段路：把成绩管理系统里求平均、找最高、排序这几个核心操作，全部改写成指针版本，并与原来的下标版本对照结果。走完这一步，你第一次说得出指针到底好在哪。

这次要做出什么

一个程序，成绩表写在代码里（{88, 76, 95, 60, 82}），做四件事：

  1. 用指针遍历把原成绩表打印出来；
  2. averageOf(const int *p, int n) 交回平均分（一位小数）；
  3. highestOf(const int *p, int n) 交回最高分；
  4. sortDescending(int *p, int n) 就地把表按从大到小排好，再打印一遍。

四个环节全部用指针：遍历写 *p 或 p[i]，函数参数是指针，排序交换的是指针指着的值。

再加一条硬要求：每个函数开头都要判空与边界检查，让「表不存在」和「表是空的」两种调用都不崩。

交付物

一份你自己写的 .cpp 源文件，建议叫 pointerstats.cpp：

  • g++ -std=c++17 -Wall -Wextra pointerstats.cpp -o pointerstats 编译通过，没有任何 warning；
  • 运行输出与下面的预期逐字一致；
  • 代码不少于 45 行（含注释与空行）。

留白任务在 实验三任务，里面有起始文件、预期输出与自查清单。

怎么算过

逐条核：

  1. 编译带 -Wall -Wextra，没有 error、也没有 warning；
  2. 四行输出逐行对上：原成绩表 88 76 95 60 82、平均分 80.2、最高分 95、排好序 95 88 82 76 60；
  3. 自己核过：总分 401、401 ÷ 5 = 80.2；
  4. 再写一份下标版跑同一组数据，两版的平均分、最高分、排序结果完全相同；
  5. 故意给统计函数传一个空表（长度 5）与一个空表（长度 0），程序不崩，而是交回你约定的那个标志；
  6. 交之前把 lab/exp-3-pointer-rewrite/自查清单.md 从头核一遍。

第 4 条是这次验收的核心：指针版和下标版算的是同一片内存，结果必须一致。 不一致就说明有一版走错了，要用打印中间值的办法找出先分岔的那一步。

自查清单

  • 遍历、平均、最高、排序四个环节都用指针，没有一处退回成 scores[i]。
  • 只读的函数标了 const，要改数据的排序函数没标。
  • 每个函数开头都判了空与边界。
  • 长度是参数传进来的，函数里没有 sizeof(p)。
  • 排序交换的是元素的值，不是两个指针变量。
  • 循环一律写 p < scores + n，没有哪一处解引用了 scores + n。
  • 平均分用了小数。
  • 说得出指针版本的一个好处与一个代价。

最可能卡在哪

交换的是指针，不是值 
int *temp = a;   // 这样只换了两个指针变量
a = b;
b = temp;        // 数组一个元素都不会动

要交换的是指针指着的值：

int temp = *a;
*a = *b;
*b = temp;
函数里用 sizeof 求长度

函数里的 p 是指针，sizeof(p) 量出来是地址的大小（本机 8），不是整张表的大小。长度必须当成另一个参数传进来——「起点加长度」是数组传参的固定搭配。

排序方向反了

按从大到小排，内层比较写的是「后面那个比擂主大就把擂主换掉」。写成小于号，排出来是从小到大。这种错不会报错，只会把顺序弄反——拿一组心里有数的数据核一遍就能抓住。

循环走过了数组末尾

for (int *p = scores; p <= scores + n; p++) 的最后一轮会解引用终点线，读到的数每次运行都不一样。条件写 p < scores + n。

两版结果不一致时怎么查

不要来回改代码。在两个版本里各加一句打印，把每一轮的下标、指针位置、累加或交换的两个值都打出来，对照着看第一步从哪儿开始不一样。分岔的那一步就是错的地方。

指针的起点不用写 & 
int *p = scores;        // 数组名本身就是首元素的地址
averageOf(scores, N);   // 传数组名进去，不用写 &

写成 &scores 反而不对：那是「整个数组的地址」，类型与 int * 对不上，编译器会拦下来。
