数组：一次声明一批变量

本节目标：用一个数组存下 10 个成绩，再按下标逐个取出来打印，并说清下标为什么从 0 开始。

三十个同学的成绩

循环那一课把「读成绩」这件事交给了机器，可循环变量 i 每轮读进来的那个 score，下一轮就被新值盖掉了。要留住一批成绩，就得有一批变量：score1、score2、……score30。

三十个变量名不好起，更麻烦的是循环用不上——循环体里的名字是同一个，score 加不了 i 这个后缀。程序里需要一个能一次声明一批变量、又能让循环按下标去取的东西。

数组：一次声明一批

数组：把同一类型的多个值排成一排连续存放、共用一个名字、用下标区分的存储方式。

三个要点都在定义里：

  • 同一类型：一批成绩都是 int，或者都是 double。类型混着的就不能用同一个数组装。
  • 连续存放：这些值在内存里挨着排，中间不留空隙。这件事在讲指针的那一课会长出很多用法，现在先记住。
  • 共用一个名字、用下标区分：整排值只有一个名字，取其中某一个，要在名字后面加方括号写下标，例如 scores[0]。

存成 arr-01.cpp 再编译：

// arr-01.cpp -- 声明一个数组，用下标往里存、往外取
#include <iostream>
using namespace std;

int main()
{
    int scores[5];              // 5 个 int，共用一个名字 scores

    scores[0] = 90;
    scores[1] = 85;
    scores[2] = 78;
    scores[3] = 92;
    scores[4] = 88;

    cout << "第 1 个成绩：" << scores[0] << endl;
    cout << "第 5 个成绩：" << scores[4] << endl;
    return 0;
}
$ g++ arr-01.cpp -o arr-01
$ ./arr-01
第 1 个成绩：90
第 5 个成绩：88

声明语句 int scores[5]; 要交代三件事：每个元素的类型（int）、数组的名字（scores）、元素的个数（5）。

数组里的每一个元素，用法与一个普通的 int 变量完全一样：能赋值、能参与运算、能被 cin 读入。区别只在于它们的名字是「数组名 + 下标」。

下标从 0 开始

下标：数组元素的位置编号，C++ 里从 0 开始数。

从 0 开始这件事，一开始总让人别扭。它来源于下标的真实含义：下标表示「从数组开头往后数了几格」。第一个元素就在开头，往后数 0 格，所以是 scores[0]；第五个元素往后数 4 格，所以是 scores[4]。因此一个 5 个元素的数组，合法的下标是 0 到 4，没有 scores[5]。

图中的内存地址，指的是内存里每个字节的位置编号。图里假设第一个元素住在 1000 号，每个 int 占 4 个字节，所以相邻两个元素的地址正好差 4。地址的完整意义要到「内存地址与取地址符」那一章才展开，这里只需要看出两件事：五个元素挨着放；下标 3 的那个元素，位置就是开头往后数 3 格。

声明与初始化

数组可以在声明的时候直接填好值，写一对花括号，值之间用逗号隔开：

int scores[5] = {90, 85, 78, 92, 88};

这套写法有几条规则值得记牢。存成 arr-02.cpp 再编译：

// arr-02.cpp -- 初始化列表：写几个就填几个，剩下的一律补 0
#include <iostream>
using namespace std;

int main()
{
    int scores[5] = {90, 85, 78};       // 只写三个，后面两个补 0
    int blank[5] = {};                  // 一对空花括号：全部为 0

    cout << "scores：";
    for (int i = 0; i < 5; i++)
    {
        cout << scores[i] << " ";
    }
    cout << endl;

    cout << "blank：";
    for (int i = 0; i < 5; i++)
    {
        cout << blank[i] << " ";
    }
    cout << endl;
    return 0;
}
$ g++ arr-02.cpp -o arr-02
$ ./arr-02
scores：90 85 78 0 0
blank：0 0 0 0 0
写法结果
int scores[5] = {90, 85, 78};只写了三个值，后面两个补 0
int blank[5] = {};全部元素都是 0
int scores[5];没有初始化，元素里是内存中原有的数据
int scores[] = {90, 85, 78};元素个数由花括号里的值数出来，这里是 3

最后一行那种省掉元素个数的写法要小心：个数由编译器去数，数错了编译器不会告诉你。这一章的数组都用 const 常量把个数写出来。

const int N = 10;
int scores[N];

const 在第 2 课讲过：被它修饰的名字，值定下来以后不允许再改。数组的元素个数必须是编译时就能确定的常量，所以声明数组的长度时正好用它：const int N = 10; 既满足这条要求，又让「10」这个数字在代码里只出现一次。

用数组存下 10 个成绩

把循环和数组拼起来，就是成绩管理系统里那张成绩表的样子：循环按下标把成绩一个个存进去，再按下标一个个取出来。

存成 arr-03.cpp 再编译，输入 10 个成绩：

// arr-03.cpp -- 用数组存下 10 个成绩，再逐个打印
#include <iostream>
using namespace std;

int main()
{
    const int N = 10;           // 元素个数必须是编译时就能定下来的常量
    int scores[N];

    cout << "请依次输入 " << N << " 个成绩：" << endl;
    for (int i = 0; i < N; i++)
    {
        cin >> scores[i];
    }

    for (int i = 0; i < N; i++)
    {
        cout << "第 " << i + 1 << " 位：" << scores[i] << " 分" << endl;
    }
    return 0;
}
$ g++ arr-03.cpp -o arr-03
$ ./arr-03

两处细节。第一，cin >> scores[i]; 直接读进数组的某个元素，读之前不需要给这个元素赋初值。第二，打印时写的是 i + 1，因为人是按第 1 个、第 2 个数数的，而下标从 0 起——把两个编号分开算，输出才符合人的习惯。

数组不记住长度

数组名只表示「这一排值从哪儿开始」，并不带着「一共几个」。想得到长度，只能自己数：用元素个数除以单个元素的字节数。

要问某个东西占多少字节，用 sizeof 运算符：写在变量或类型前面，得到它占用的字节数。存成 arr-06.cpp 再编译：

// arr-06.cpp -- sizeof：数组占多少字节，里面有几个元素
#include <iostream>
using namespace std;

int main()
{
    int scores[5] = {90, 85, 78, 92, 88};

    cout << "整个数组占的字节数：" << sizeof scores << endl;
    cout << "一个元素占的字节数：" << sizeof scores[0] << endl;
    cout << "元素个数：" << sizeof scores / sizeof scores[0] << endl;
    return 0;
}
$ g++ arr-06.cpp -o arr-06
$ ./arr-06
整个数组占的字节数：20
一个元素占的字节数：4
元素个数：5

sizeof scores 得到 20（5 个 int），sizeof scores[0] 得到 4（一个 int），两者相除就是元素个数。这是上一节那张内存示意图的算术版。

不过循环里更常见的写法还是 const int N = 10; 加 i < N：个数是你自己定的，写在常量里，改一处就全改。

越界：编译器不拦

下标超出范围不会让编译器报错。存成 arr-04.cpp 再编译，这个程序能编译、能跑：

// arr-04.cpp -- 越界访问：编译器不拦，程序照跑
#include <iostream>
using namespace std;

int main()
{
    int scores[5] = {90, 85, 78, 92, 88};

    cout << "scores[0] = " << scores[0] << endl;
    cout << "scores[4] = " << scores[4] << endl;
    cout << "scores[5] = " << scores[5] << endl;      // 下标 5 不存在
    return 0;
}
$ g++ -Wall arr-04.cpp -o arr-04
arr-04.cpp:11:31: warning: array index 5 is past the end of the array (that has type 'int[5]') [-Warray-bounds]
$ ./arr-04
scores[0] = 90
scores[4] = 88
scores[5] = 1

第三行打印出来的 1 不属于这张成绩表。scores 后面那块内存里装着别的东西，程序照着「开头往后数 5 格」把那里的字节当成一个 int 读了出来，是什么值完全说不准，换台机器、换个编译方式都可能不一样。

越界读写

-Wall 打开了边界检查的提醒，编译器在编译时就能看出下标 5 越过了 5 个元素的数组，于是给出警告。要是编译时不带 -Wall，这一行警告不会出现，程序照样编译通过——这正是越界最麻烦的地方：它不报错，只是悄悄地读写别处的数据。

读越界的数据，最多是算出一个没有意义的数；写越界更糟，下面这三行的位置关系就是问题所在：

int victim = 7;
int scores[5] = {90, 85, 78, 92, 88};
scores[5] = 99;          // 这块地方不属于 scores
cout << victim;          // victim 可能已经不是 7 了

scores[5] = 99; 会写到 scores 后面的那块内存上。那块内存里可能正好住着另一个变量，于是那个变量被无声无息地改掉了，而报错的位置离出问题的地方很远，排查起来非常费劲。

写循环访问数组时，把边界检查一遍：i 从 0 开始，条件写 i < N，这样最后一轮的下标正好是 N - 1，一格都不越。

没初始化的累加

数组元素在赋初值之前，里面是内存中原有的数据。存成 arr-05.cpp：

// arr-05.cpp -- 反例：数组没初始化就直接累加
#include <iostream>
using namespace std;

int main()
{
    int scores[5];                  // 没有初始化，元素里是内存中原有的数据
    int total = 0;

    for (int i = 0; i < 5; i++)
    {
        total += scores[i];         // 读到的是没有意义的值
    }

    cout << "总分：" << total << endl;
    return 0;
}
累加之前先有值

这个程序编译得过，运行也不会报错，但打出来的「总分」是一串没有意义的数字：五个元素从没被赋过值，total += scores[i] 累加进去的是内存里原有的数据。

总分算得不对时，先看两个地方：累加器有没有初值，数组的元素是不是都赋过值。这一条与上一节「越界」是同一类问题——程序不报错，结果不对。

arr-02.cpp 里那种 int blank[5] = {}; 是给数组一次性清零的省事写法，需要从 0 开始累加时用得上。

动手做：改数组看变化

数组的语法不多，容易出错的地方集中在起点和边界。下面三步都在刚才的文件上改，每一步都能立刻看到差别。

练习 改一改，看下标与边界

第 1 步 · 数一数下标。编译运行 arr-01.cpp，然后加一行 cout << scores[5] << endl;，带上 -Wall 编译，看编译器给什么警告；再去掉这一行。

第 2 步 · 改个数。把 arr-03.cpp 里的 const int N = 10; 改成 5，重新编译运行。注意两个循环都用的 N，只改了这一个地方，两处都跟着变了。

第 3 步 · 少写一个初值。把 arr-02.cpp 里 int scores[5] = {90, 85, 78}; 改成 int scores[5] = {90, 85, 78, 92};，重新编译运行，看 scores 那一行最后几个数字变成什么。

第 4 步 · 数一下字节。把 arr-06.cpp 里的 int 换成 double，重新编译运行，看三个数字分别变成多少，想一想「元素个数」那一行为什么没变。
