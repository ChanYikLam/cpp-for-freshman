分支：让程序会判断

本节目标：用 if / else if / else 给成绩划出及格线与等级，并拦住输错的分数。

成绩管理系统需要第二个本事

到上一课为止，程序会算数了，但它对每个分数都一视同仁：算完平均分就结束。成绩管理系统还得回答两类问题——「这个人及格没有」「这个分数该给什么等级」——还要拦住输错的分数。这三件事都是「判断」，也就是让程序在不同情况下走不同的路。

让程序走不同的路

先看一个具体的要求：分数大于等于 60 就打印「及格」，否则打印「不及格」。存成 branch-01.cpp 编译运行：

#include <iostream>

int main()
{
    int score = 87;

    if (score >= 60)
    {
        std::cout << "及格" << std::endl;
    }
    else
    {
        std::cout << "不及格" << std::endl;
    }

    return 0;
}
$ ./branch-01
及格

把它拆成三段来读：

  • if (score >= 60) 是条件。括号里的 score >= 60 是一个表达式，它算出来的值是 true 或 false。
  • 紧跟其后的一对花括号里，是条件为真时执行的东西。
  • else 后面那对花括号里，是条件为假时执行的东西。

这种「如果……否则……」的结构叫 if 语句，它模仿的是英语里的说法。C++ 判定条件的方式很宽松：任何值都能拿来当条件，0 算假，非 0 算真。所以 if (score) 这种写法也能编译，只要 score 不是 0 就为真——但这种写法读代码的人要停下来想一下，不如把关系写清楚。

括号里那种比大小的表达式叫关系表达式，用到的符号有六个：

运算符含义写法别和它混
==等于score == 60= 是赋值，不是比较
!=不等于score != 60
>大于score > 60
<小于score < 60
>=大于或等于score >= 60顺序不能反写
<=小于或等于score <= 100顺序不能反写

上一课见过这几个符号算出来的 true/false，这一课终于用到它们身上。

多岔路口：else if 链

及格线只有两档，等级有四五档。要求是：90 分以上优，80 到 89 良，70 到 79 中，60 到 69 及格，60 以下不及格。存成 branch-02.cpp：

#include <iostream>

int main()
{
    int score = 72;

    if (score >= 90)
    {
        std::cout << "等级：优" << std::endl;
    }
    else if (score >= 80)
    {
        std::cout << "等级：良" << std::endl;
    }
    else if (score >= 70)
    {
        std::cout << "等级：中" << std::endl;
    }
    else if (score >= 60)
    {
        std::cout << "等级：及格" << std::endl;
    }
    else
    {
        std::cout << "等级：不及格" << std::endl;
    }

    return 0;
}
$ ./branch-02
等级：中

这个链子的执行方式值得说明清楚，因为它解释了为什么每个条件只写半边：

程序从上往下一个一个判。score 是 72，第一个条件 72 >= 90 为假，跳过去；第二个 72 >= 80 也为假；第三个 72 >= 70 为真，执行它那段，然后整条链子结束，下面的一律不看。

正因为「一旦为真，后面的都不判」，第二个条件才有资格只写 score >= 80。走到这一句的时候，「score 小于 90」这个条件已经被第一个分支确认过了，不必再写一遍。如果写成 score >= 80 && score < 90，结果一样，但多写的部分是白写。

顺序写错，整条链子废掉

把 score >= 60 挪到最前面，89 分、95 分都会走进「及格」那个分支——因为「72 大于等于 60」这件事对任何 60 分以上的分数都成立，第一个条件一旦为真，后面的等级判断全都不执行了。

写 else if 链的规矩：从最严格的条件开始，范围从窄到宽往下排。这也是为什么最后的 else 通常留给「其他所有情况」。

亲手写一条分支

练习 第 1 步 · 改一行，看分支怎么拐弯

把 branch-01.cpp 里的 int score = 87; 分别改成 59、60、100，每改一次重新编译运行，记下三次输出。60 这一次要特别看清：「大于或等于」这个说法在等于分档线时落在哪一档。

$ ./branch-01
及格

再把它改回 87，把条件从 score >= 60 改成 score > 60，看 60 分时输出会不会变。「大于」和「大于或等于」的差别，只在取到分档线那一个数时露出来，所以要专门拿它试一次。

练习 第 2 步 · 自己写等级判断

打开 branch-02.cpp，把那条 else if 链改成五档里的另一套规则试试：90 分以上「优」、80 到 89「良」、70 到 79「中」、60 到 69「及格」、60 以下「不及格」——它已经写好了，先把它读懂，再按顺序念一遍每个条件，看能不能说出「为什么每个条件只写半边」。

然后把 int score = 72; 改成 95、85、65、30 各跑一次，确认四个数分别落到哪一档。

练习 第 3 步 · 亲手制造两个坑，再爬出来

坑一：把 branch-01.cpp 的 score >= 60 改成 score = 60，编译运行。它会打印「及格」——把 score 打印出来看看它变成了几。然后找出编译器给的那行 warning，读一遍。

坑二：把 branch-02.cpp 里那条链子的顺序打乱，把 score >= 60 挪到最前面，用 95 分跑一次，看它给出什么等级。

这两个实验各花两分钟，换来的是以后一眼就能认出这类错。

四个会咬人的坑

if 的语法短，但写错的方式很集中。四个坑全在本课程的常见错误清单里，一个一个看。

坑一：把 = 写成 ==。 存成 branch-04.cpp：

#include <iostream>

int main()
{
    char grade = 'B';

    if (grade = 'A')
    {
        std::cout << "优秀" << std::endl;
    }
    else
    {
        std::cout << "这次不是优秀" << std::endl;
    }

    return 0;
}
$ ./branch-04
优秀

grade 明明存的是 B，程序却走了「优秀」那条路。原因是 = 是赋值：grade = 'A' 把 'A' 写进了 grade，同时这个赋值表达式的值是刚赋进去的那个值，也就是 'A'，非 0，于是条件为真。

branch-04.cpp:7:15: warning: using the result of an assignment as a condition without parentheses [-Wparentheses]
    7 |     if (grade = 'A')
      |         ~~~~~~^~~~~

编译器其实察觉到了，它给了一行 warning，说「你在条件里用了赋值的结果」。这一行不要跳过——这是唯一一次提醒。不改的话程序会一直走错，编译和运行都不会再报错。而 branch-03.cpp 是同一段代码写对的样子：if (grade == 'A')，输出「这次不是优秀」。

坑二：if 后面多写一个分号。 存成 branch-09.cpp：

#include <iostream>

int main()
{
    int score = 45;

    if (score >= 60);
    {
        std::cout << "及格" << std::endl;
    }

    return 0;
}
$ ./branch-09
及格

45 分被判成了及格。原因是那个分号：if (score >= 60); 里的分号本身就是一条空语句，它成了 if 唯一管着的东西。下面那对花括号跟 if 已经没关系了，是一段普通代码，无条件执行。

编译时其实也有一行提醒，说的是同一件事：

branch-09.cpp:7:21: warning: if statement has empty body [-Wempty-body]
    7 |     if (score >= 60);
      |                     ^
1 warning generated.

if statement has empty body 就是「这个 if 的身体是空的」——它在告诉你那个分号下面什么都没有。

这一条和第一课那个漏分号的错误是同一个道理的两面：分号是语句的结束标记，写在哪儿就在哪儿切一刀。

坑三：把数学写法直接搬过来。 数学课上写 60 \le score \le 100 表示「在 60 到 100 之间」。C++ 不接受这个写法。存成 branch-07.cpp：

#include <iostream>

int main()
{
    int score = 150;

    if (60 <= score <= 100)
    {
        std::cout << "分数合法" << std::endl;
    }
    else
    {
        std::cout << "分数不合法" << std::endl;
    }

    return 0;
}
$ ./branch-07
分数合法

150 分被判成了合法分数。原因是关系运算符也是从左往右算的：60 <= score 先算，150 让它得到 true，在需要数值的场合 true 是 1；接着算 1 <= 100，得 true。两个条件串成了一个，无论分数多大都会说合法。

C++ 里要写区间，必须用「并且」把两个条件连起来。存成 branch-08.cpp：

#include <iostream>

int main()
{
    int score = 150;

    if (score >= 60 && score <= 100)
    {
        std::cout << "分数合法" << std::endl;
    }
    else
    {
        std::cout << "分数不合法" << std::endl;
    }

    return 0;
}
$ ./branch-08
分数不合法

坑四：用 == 比较两个小数。 上一课已经拆过这一处：0.1 + 0.2 == 0.3 的结果是 false。在分支里的后果更隐蔽——条件永远不成立，那个分支里的话永远不执行，你看不到任何报错。

逻辑运算符：把条件拼起来

上面修 branch-07 用到的 && 是逻辑运算符。三个逻辑运算符的作用是把两个条件组合成一个：

运算符读法什么时候为真例子
&&并且两边都为真score >= 60 && score <= 100
||或者至少一边为真grade == 'A' || grade == 'B'
!非把真变假、假变真!(score < 60)

它们能拼起来用，而且优先级低于关系运算符——score >= 60 && score <= 100 里，两个比较会先算完再算 &&，所以括号可以省。拿不准的时候加括号，代价是零。

&& 有一个必须知道的行为叫短路求值：它先看左边，如果左边已经为假，整个表达式一定为假，右边就不算了。|| 对称：左边为真就不看右边。

短路不只是省时间，它是可以依靠的写法。比如「先确认分母不为 0，再去除」：

if (count != 0 && total / count > 60)

左边为假时右边根本不执行，那个除法就不会发生。反过来，如果把两个条件调换顺序，total / 0 就会真的算下去。

switch：等值的判断

如果判断的对象是「等于哪几个具体值」，C++ 还有一条路叫 switch 语句。存成 branch-06.cpp：

#include <iostream>

int main()
{
    char grade = 'B';

    switch (grade)
    {
    case 'A':
        std::cout << "优秀" << std::endl;
        break;
    case 'B':
        std::cout << "良好" << std::endl;
        break;
    case 'C':
        std::cout << "及格" << std::endl;
        break;
    default:
        std::cout << "不及格" << std::endl;
        break;
    }

    return 0;
}
$ ./branch-06
良好

读法：switch (grade) 拿 grade 的值去和下面每个 case 后面的值比，相等就跳到那一行往下执行；default 是「都不匹配」时走的。break 的作用是「执行到这里就跳出 switch」——漏掉 break，程序会继续往下执行下一个 case 的内容，这个现象叫「贯穿」。

什么时候用 switch、什么时候用 if：

  • 判断等于几个具体值，而且值的个数多（菜单选择、等级字符），用 switch 更整齐，也更容易发现漏掉的情况。
  • 判断范围（分数段）、条件里要写 && 或 ||、或者要判两个变量之间的关系，只能用 if。switch 的 case 后面只接受常量，写不了 case >= 60。

主线项目：把输入接进判断

第 4 课那个读成绩的程序有一个漏掉的地方：用户敲了 abc 或者敲了 150，程序会一路错下去。现在有判断能力了，可以补上这一环。存成 branch-05.cpp：

#include <iostream>

int main()
{
    int score = 0;

    std::cout << "请输入成绩（0 到 100）：";
    while (!(std::cin >> score) || score < 0 || score > 100)
    {
        std::cout << "这个数不能用，请重新输入一个 0 到 100 的整数：";
        std::cin.clear();
        std::cin.ignore(1000, '\n');
    }

    std::cout << "收到的成绩是 " << score << std::endl;

    return 0;
}
$ ./branch-05
请输入成绩（0 到 100）：101
这个数不能用，请重新输入一个 0 到 100 的整数：abc
这个数不能用，请重新输入一个 0 到 100 的整数：-5
这个数不能用，请重新输入一个 0 到 100 的整数：87
收到的成绩是 87

这一段把前两课的东西全用上了：

  • std::cin >> score 这个表达式本身的值可以当条件用：读成功为真，读失败为假，所以 !(std::cin >> score) 就是「读失败了」；
  • 三个条件用 || 连起来：读失败、太小、太大，任意一个成立就要重问；
  • && 的短路特性在这里换成 || 同样有用：读失败时，score < 0 那半边已经为假，但 !(...) 已经为真，整个条件成立，直接进去重问；
  • std::cin.clear() 与 std::cin.ignore(1000, '\n') 照第 4 课那样，清掉失败状态、丢掉坏输入。

while (...) 的意思是「只要括号里为真就重复做下面那段」。循环是下一课的主角，这里先当作「一直重问直到输入能用」来用。

到这里，成绩管理系统学会了第一件真正有用的事：拦住错的输入。下一步是给这个分数贴上等级——branch-02.cpp 那段 else if 链直接接在后面就能用。
