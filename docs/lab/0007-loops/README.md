# 动手任务：读入并累加一批成绩

**几分钟能做完**：30 到 40 分钟。
**交付物**：一份能编译、能跑的 `loops.cpp`，三组输入下输出都与「预期输出」逐字一致。

## 这个任务要做什么

第 7 课把「读一遍成绩并累加」讲完了。这次换一个输入约定，自己写一遍：

1. 先读一个整数 `n`，表示这一批有几个成绩；
2. 循环 `n` 轮，每轮读一个成绩加进总分；
3. 打印这一批的个数与总分。

个数由输入决定，所以 `n` 是 3 也好、是 5 也好，**代码一个字都不用改**。

## 文件清单

## 怎么编译、怎么跑

```sh
g++ -std=c++17 -Wall -Wextra loops.cpp -o loops
```

```sh
./loops < 5个成绩.in
./loops < 3个成绩.in
./loops < 1个成绩.in
```

### Dev-C++ 用户对照

| 命令行里做的 | Dev-C++ 里点的 |
| --- | --- |
| 打开 `loops.cpp` | 文件 → 打开 |
| `g++ ... -o loops` | 按 **F11**；`-Wall` 在「工具 → 编译选项」里勾上「显示更多警告」 |
| `./loops < 5个成绩.in` | 做不到，手动敲：先敲 `5` 回车，再依次敲 `90` `85` `78` `92` `88`，每个一行 |

## 预期输出

```term
$ ./loops < 5个成绩.in
请输入成绩个数：共 5 个成绩，总分 433
```

```term
$ ./loops < 3个成绩.in
请输入成绩个数：共 3 个成绩，总分 253
```

```term
$ ./loops < 1个成绩.in
请输入成绩个数：共 1 个成绩，总分 88
```

从输入文件读的时候，屏幕上看不到你敲的那些数字，所以第一行只有提示语。这是正常的。

动手算一下：90 + 85 + 78 + 92 + 88 = 433。**输出的数字要和你手算的完全一致**，不是「差不多」。

## 要点

- **累加器进循环之前必须是 0**。给别的数，总分就从那个数开始往上加。
- **循环次数由 `n` 决定**，不是写死的 5。写死的话，`3个成绩.in` 会读进去 `90 85 78` 之后还去读一个不存在的数。
- **每一轮读一个、加一个**：读进来的那个值先放进一个变量，再加进总分。
- 循环变量从 1 数到 `n`（`i <= n`），或者从 0 数到 `n - 1`（`i < n`），两种都对——起始值和边界要配成一套。

## 卡住了怎么办

按这个顺序来：

1. **读报错**：看编译器给的文件名与行号，再看那一行的上一行。
2. **看上面的「要点」**。
3. **看 `自查清单.md`**，一条一条核。
4. 还是卡住，才去看 `lab/solutions/0007-loops/loops.cpp`。那是**另一份**文件，抄之前先想清楚自己那处差在哪。

## 常见现象对照

| 你看到的 | 多半是什么 |
| --- | --- |
| 总分永远是 0 | 循环体里读了成绩，但没有加进累加器 |
| `3个成绩.in` 的总分把后面的数也算进去了 | 循环次数写死了 5 轮，多读了两轮 |
| 总分比手算少一个成绩 | 边界写 `i < n` 但起始值写成 1，少跑了一轮 |
| 程序停在那儿等输入 | 个数读进来是 0 或负数，或者读个数的语句漏了 |
