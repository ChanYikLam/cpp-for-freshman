# 自查清单：实验三 · 用指针改写核心操作

交之前逐条核。**每条都能自己验。**

## 一、编译

- [ ] `g++ -std=c++17 -Wall -Wextra pointerstats.cpp -o pointerstats` 退出码是 0。
- [ ] 没有 `error`，也没有 `warning`。

## 二、逐行对输出

- [ ] `./pointerstats` 打印四行。
- [ ] 第 1 行 `原成绩表：88 76 95 60 82`。
- [ ] 第 2 行 `平均分：80.2`。
- [ ] 第 3 行 `最高分：95`。
- [ ] 第 4 行 `排好序：95 88 82 76 60`——**从大到小**。
- [ ] 自己核过：总分 401、平均分 80.2。

## 三、指针版与下标版结果必须一致

- [ ] 把成绩表改成另一组数（例如 `{60, 100, 72, 85, 91}`），四个结果都跟着对。
- [ ] 再写一份**下标版**（`scores[i]`）跑同一组数据，两版的平均分、最高分、排序结果**完全相同**。
- [ ] 两版不一致时，用打印中间值的办法找出是哪一步先分岔的——不要直接改代码碰运气。

## 四、必须能拦住的情况

- [ ] 故意给统计函数传一个空表（`nullptr` 配长度 5），程序**不崩**，而是交回一个说得清的标志。
- [ ] 故意给统计函数传长度 0，程序**不崩**（`p[0]` 那一步被挡住了）。
- [ ] 排序函数收到 `n <= 1` 时什么都不做，也不会越界。
- [ ] 成绩表里有重复的最高分（例如两个 95）时，排序结果仍然正确。

## 五、代码与交付物

- [ ] 代码不少于 45 行（含注释与空行）。
- [ ] 四个环节（遍历、平均、最高、排序）都用指针，没有一处退回成 `scores[i]`。
- [ ] 只读的函数标了 `const`，要改数据的排序函数没标。
- [ ] 每个函数开头都有判空与边界检查。
- [ ] 长度是**参数传进来**的，函数里没有 `sizeof(p)`。
- [ ] 排序交换的是元素的值：`int temp = *a; *a = *b; *b = temp;`。
- [ ] 循环一律用 `p < scores + n`，没有哪一处解引用了 `scores + n`。

## 六、收尾

- [ ] 说得出这句话：**指针版和下标版算的是同一片内存，所以结果必须一致。**
- [ ] 说得出指针版本的一个好处与一个代价（例如：好处是表达「起点加步长」很直接；
      代价是边界要自己盯住，走过头也不报错）。
