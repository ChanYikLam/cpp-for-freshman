# 动手任务：读入三门成绩算平均分

**几分钟能做完**：20 到 30 分钟。
**交付物**：一份能编译、能跑的 `average3.cpp`，输出与下面的「预期输出」逐字一致。

## 这个任务要做什么

把第 4 课的 `io-06.cpp` 那份「成绩写死在代码里」的程序，改成能对着人用的版本：

1. 提示用户输入三门课的成绩；
2. 读进来，算出总分与平均分（平均分保留一位小数）；
3. 第一次输入不是三个数时，清掉失败状态、丢掉坏输入，重新问一次。

这就是成绩管理系统里每一次读入都要走的形状。

## 文件清单

| 文件 | 是什么 |

| `average3.cpp` | **留白**的源文件，四处 `TODO` 等你补。能编译，但读进来的值不对，输出与预期不符 |

## 怎么编译、怎么跑

在存放这些文件的目录下打开终端：

```sh
g++ -std=c++17 -Wall -Wextra average3.cpp -o average3
```

第一份输入（正常）：

```sh
./average3 < 成绩.txt
```

第二份输入（先敲错一次）：

```sh
./average3 < 乱输入.txt
```

### Dev-C++ 用户对照

| 命令行里做的 | Dev-C++ 里点的 |
| --- | --- |
| 打开 `average3.cpp` | 文件 → 打开，选中 `average3.cpp` |
| `g++ ... -o average3` | 按 **F11**（编译并运行）；`-Wall` 在「工具 → 编译选项 → 代码生成/优化 → 显示更多警告」里勾上 |

## 预期输出

第一次跑（`./average3 < 成绩.txt`）：

```term
$ ./average3 < 成绩.txt
请输入三门课的成绩（用空格或回车分开）：三门成绩：92.0、88.0、87.5
总分：267.5
平均分：89.2
```

第二次跑（`./average3 < 乱输入.txt`），第二行是你的程序回的那句话：

```term
$ ./average3 < 乱输入.txt
请输入三门课的成绩（用空格或回车分开）：这组输入不是三个数，请重新输入：三门成绩：92.0、88.0、87.5
总分：267.5
平均分：89.2
```

逐行对上：第一行末尾接着你输入的数字（提示语后面没有换行，这是正常的）；最后一行的平均分必须是 **89.2**，不是 89、也不是 89.0。

## 要点

- **三个成绩声明成 `double`**。成绩本身可能是 `87.5`，用 `int` 会在读入那一步就把小数切掉。
- **科目数只该有一个定义处**：`const int kSubjectCount = 3;`，以后改成五门只改这一行。
- **小数在算的那一步就要留住**：除法的两个操作数里至少有一个是小数，平均分才有小数部分。
- **每个读取前面配一句提示语**，并说清要输入什么、怎么分隔。

## 卡住了怎么办

按这个顺序来，别一上来就翻参考解：

1. **读报错**。终端里的 `error`、`warning` 都是编译器说的，先看它给的文件名与行号，再看那一行的上一行。
2. **看这份 README 的「要点」**。四处的错通常就在那四条里。
3. **看 `自查清单.md`**，一条一条核。
4. 还是卡住，才去对照 `lab/solutions/0004-input-output/average3.cpp`。它是**另一份**文件，不是你的，抄之前先想清楚自己那处差在哪。

## 常见现象对照

| 你看到的 | 多半是什么 |
| --- | --- |
| 平均分打出 `89.0` | 读进来的成绩或分母里没有小数，除法走的是整数除法 |
| 敲了 `abc` 之后一路错到底、平均分是 0 | `cin` 进了失败状态，而且坏输入还留在输入队列里 |
| 程序停在那儿不动、敲键盘没反应 | 少写了提示语，或者少了一次读取 |
