# 动手任务总览

这门课不是「读完就算」：每一课后面都有一段要你亲手敲的东西。这个目录就是那些任务的存放处。

**先看这一页，再去翻具体的任务目录。**

## 你需要什么环境

只要一样东西：**一个能编译 C++ 的编译器** `g++`。不需要装测试框架、不需要联网、不需要额外下载任何东西。

| 你的系统 | 怎么准备 |
| --- | --- |
| Windows（推荐） | 装 MSYS2，再在这个终端里装工具链：`pacman -S --needed base-devel mingw-w64-ucrt-x86_64-toolchain`；编辑器用 VS Code 加 C/C++ 扩展 |
| Windows（已经在用 Dev-C++） | 不用重装任何东西。Dev-C++ 里自带的编译器能按 C++ 标准编译本课程全部代码，**按 F11 就是「编译并运行」**；每个任务目录的 README 里都有一张「命令行 ↔ Dev-C++」对照表 |
| macOS | `xcode-select --install`。`g++ --version` 打印出 `Apple clang` 是正常的，照敲就行 |
| Linux | 用发行版的包管理器装 `gcc-c++` 或 `build-essential` |

本书所有命令一律按命令行写。用 Dev-C++ 的同学照每个任务 README 里的对照表操作即可。

## 一份任务目录里有什么

| 文件 | 作用 |
| --- | --- |
| `README.md` | 这一小步要做什么、要点是什么、**怎么编译怎么跑**、**预期输出**（照着逐行对） |
| `<任务>.cpp` | **留白**的源文件，`TODO` 标出要补的地方。能编译，但输出与预期不符——这是故意的 |
| `<任务>.in` 或 `某某输入.txt` | 需要标准输入的，给一份现成的输入 |
| `预期输出.txt` | 预期输出的原文，供你对答案 |
| `自查清单.md` | 可核验的检查项：输出第几行应该是什么、哪些情况必须能拦住 |
| `../lab/solutions/<同名目录>/` | **参考解**，与任务分开放，做完才对照 |

## 怎么跑一个任务

以 `0004-input-output` 为例，在存放那个目录里的文件的目录下打开终端：

```sh
g++ -std=c++17 -Wall -Wextra average3.cpp -o average3
```

```sh
./average3 < 成绩.txt
```

Windows 的 PowerShell / MSYS2 终端里运行写 `./average3.exe` 或 `.\average3.exe`。

**`-Wall -Wextra` 别省**：它们是「把编译器能发现的疑点都提醒出来」，不改程序行为，只是多打印提醒。本课程要求的「编译无警告」，只有带上这两个选项才看得见。

## 卡壳顺序（重要）

**照这个顺序来，别跳到最后一步**：

1. **读报错**。终端里的 `error`、`warning`、`note` 是编译器说的；先看它给的文件名与行号，再看那一行的上一行。编译器一次只报它最先撞上的那个问题。
2. **看这个任务的 README 的「要点」**。多数错就出在那几条里。
3. **看 `自查清单.md`**，一条一条核。
4. **看该课的课件正文**（`lessons/` 里的同名页面），找可以借鉴的形状。
5. **最后才看 `lab/solutions/<同名目录>/`**。它是**另一份文件**，不是你的；对照之前先想清楚自己那处差在哪，抄过去等于没做。

**算得不对时先别改代码**：在循环里打印每一轮的下标与累加结果，先看清哪一格不对。改之前先知道错在哪一步。

## 一句实话

这些任务一天能做完一个，但**看懂不等于写得出**。真正让你长本事的是那次
「编译报错 → 想明白 → 改对 → 再编译」，一个都别绕过去。
